Bucket

Bucket은 Object Storage 안에서 객체 데이터를 저장하는 논리 컨테이너이다. 버킷 생성 후 객체 업로드와 브라우저 조회를 수행할 수 있다.

  • 화면 위치: Storage > Buckets
  • 설명: 생성된 버킷 목록과 버킷 생성 버튼을 확인하는 화면이다.

버킷 목록 화면에서는 버킷 이름, 상태, 연결된 Object Storage, 사용량, 계정 정보를 확인할 수 있다. 화면 예시에서는 아직 생성된 버킷이 없어 데이터 없음 상태로 표시된다. 상단의 Create Bucket 버튼을 통해 신규 버킷을 생성할 수 있으며, 검색 입력창과 Projects 토글을 사용해 조회 범위를 조정할 수 있다.

  • 화면 위치: Storage > Buckets > Create Bucket
  • 설명: 객체 데이터를 저장할 버킷의 이름, 저장소, 할당량과 정책 옵션을 입력하는 화면이다.

버킷 생성 화면에서는 버킷 이름, Object Storage, Quota in GiB, 암호화, 버전 관리, 객체 잠금, 버킷 정책을 설정한다. 화면 예시에서는 hpstorage01 이름의 버킷을 hpBucket 저장소에 생성하고, 할당량은 15 GiB로 지정되어 있다. Encryption, Versioning, Object Lock은 비활성화되어 있으며, Bucket Policy는 Private으로 선택되어 있다.

  • 화면 위치: Storage > Buckets
  • 설명: 신규 버킷 생성 후 목록에 Created 상태로 표시되는 화면이다.

버킷 생성이 완료되면 목록에 신규 버킷이 추가된다. 화면 예시에서는 hpstorage01 버킷이 Created 상태로 표시되며, Object Storage는 hpBucket, Size는 0, Account는 admin으로 표시된다. 목록에서 버킷 이름을 선택하면 해당 버킷의 상세 화면과 브라우저 화면으로 이동할 수 있다.

  • 화면 위치: Storage > Buckets > Bucket Detail > Details
  • 설명: 선택한 버킷의 상세 속성과 접근 정보를 확인하는 화면이다.

버킷 상세 화면에서는 버킷 ID, 이름, 상태, Object Storage, 크기, URL, Access Key, Secret Key, 계정, 생성 시각, 할당량, 암호화 여부를 확인할 수 있다. 화면 예시의 버킷은 hpstorage01이며 상태는 Created, Object Storage는 hpBucket, 할당량은 15로 표시된다. 오른쪽 상단의 작업 버튼을 통해 버킷 편집 또는 삭제 작업을 수행할 수 있다.

  • 화면 위치: Storage > Buckets > Bucket Detail > Browser > Upload
  • 설명: 버킷에 업로드할 파일과 업로드 경로, 메타데이터를 입력하는 화면이다.

객체 업로드 화면에서는 파일을 드래그하거나 클릭하여 업로드 대상을 선택할 수 있다. 화면 예시에서는 testFile01, testFile02, testFile03 파일이 업로드 목록에 추가되어 있다. Upload path에는 객체가 저장될 경로를 입력할 수 있고, Metadata 영역에서는 객체에 부여할 key-value 쌍을 추가할 수 있다.

객체 업로드 경로와 메타데이터 입력 화면

  • 화면 위치: Storage > Buckets > Bucket Detail > Browser > Upload
  • 설명: 업로드할 객체의 저장 경로와 메타데이터를 입력한 화면이다.

객체 업로드 화면에서 Upload path와 Metadata를 입력하면 업로드되는 객체에 경로와 메타데이터를 함께 적용할 수 있다. 화면 예시에서는 Upload path에 testFiles가 입력되어 있으며, Metadata 영역에는 key와 value 입력 필드가 표시된다. 사용자는 필요한 경우 Add key value pair를 통해 추가 메타데이터 항목을 등록한 뒤 Upload 버튼으로 업로드를 실행한다.

  • 화면 위치: Storage > Buckets > Bucket Detail > Browser
  • 설명: 버킷 내부 경로와 업로드된 객체 목록을 확인하는 화면이다.

Browser 탭에서는 버킷 내부의 객체와 경로를 조회할 수 있다. 화면 예시에서는 testFiles 경로 아래에 testFile01, testFile02, testFile03 객체가 표시되며, 각 항목의 크기와 마지막 갱신 시각을 확인할 수 있다. 상단의 검색 입력창, Search 버튼, Refresh 버튼, Upload 버튼을 사용해 객체 조회와 업로드 작업을 수행할 수 있다.

  • 화면 위치: Storage > Buckets > Bucket Detail > Details
  • 설명: 선택한 버킷의 상세 속성과 접근 정보를 추가로 확인하는 화면이다.

버킷 상세 화면에서는 버킷 상태, ID, 계정, 생성 시각, Object Storage, URL, 접근 정보, 할당량, 암호화 여부를 확인할 수 있다. 이 화면은 버킷 상세 정보를 추가로 보여주는 보조 예시이다.

주요 작업

Bucket 생성

  1. 상단 메뉴에서 Storage > Buckets로 이동한다.
  2. Create Bucket 버튼을 선택한다.
  3. Bucket 이름, Object Storage, Quota, 정책 옵션을 입력한다.
  4. 설정을 저장한 뒤 목록에서 Created 상태를 확인한다.

객체 업로드

  1. Bucket 상세 화면에서 Browser 탭을 연다.
  2. Upload 작업을 선택한다.
  3. 업로드할 파일, 저장 경로, 필요한 메타데이터를 입력한다.
  4. 업로드 후 Browser 화면에서 객체가 의도한 경로에 표시되는지 확인한다.

Bucket 상세 및 Browser 조회

  1. Bucket 목록에서 대상 Bucket을 선택한다.
  2. 상세 화면에서 상태, Object Storage, 정책 옵션을 확인한다.
  3. Browser 탭에서 내부 경로와 객체 목록을 확인한다.

입력 항목

버킷 생성 입력 화면

항목 설명
Name 생성할 버킷 이름을 입력한다.
Object Storage 버킷을 생성할 객체 저장소를 선택한다.
Quota in GiB 버킷에 할당할 최대 용량을 GiB 단위로 입력한다.
Encryption 버킷 암호화 사용 여부를 선택한다.
Versioning 객체 버전 관리 사용 여부를 선택한다.
Object Lock 객체 잠금 기능 사용 여부를 선택한다.
Bucket Policy 버킷 접근 정책을 선택한다. 화면 예시에서는 Private이 선택되어 있다.

객체 업로드 입력 화면

항목 설명
Upload file area 업로드할 파일을 클릭하거나 드래그하여 추가한다.
Upload path 객체를 업로드할 버킷 내부 경로를 입력한다.
Metadata 객체에 부여할 메타데이터를 key-value 형식으로 입력한다.

객체 업로드 경로와 메타데이터 입력 화면

항목 설명
Upload path 객체가 저장될 버킷 내부 경로를 입력한다. 화면 예시에서는 testFiles가 입력되어 있다.
key 메타데이터 키를 입력한다.
value 메타데이터 값을 입력한다.
Add key value pair 메타데이터 key-value 쌍을 추가한다.

상태 및 제약 조건

  • Bucket 생성이 완료되면 목록의 State 값이 Created로 표시된다.
  • 객체가 없으면 Size 값은 0으로 표시될 수 있다.
  • Bucket 이름, 접근 정책, Quota는 생성 후 운영 영향이 크므로 사용 목적과 접근 범위를 먼저 정해야 한다.
  • 동일 경로에 같은 이름의 객체를 업로드할 때 실제 결과는 Versioning 지원 여부와 Provider 정책에 따라 달라질 수 있다.

주의사항

  • 버킷 이름과 접근 정책은 생성 후 운영 영향이 있을 수 있으므로, 사용 목적과 접근 범위를 확인한 뒤 설정해야 한다.
  • Quota in GiB 값은 계정 또는 프로젝트의 객체 저장소 사용량 제한과 함께 검토해야 한다.
  • 버킷 삭제는 저장된 객체 데이터에 영향을 줄 수 있으므로 삭제 전 객체 목록과 사용 여부를 확인해야 한다.
  • 동일한 경로에 같은 이름의 객체가 존재할 경우 덮어쓰기 또는 버전 생성 동작은 객체 저장소 설정에 따라 달라질 수 있으므로 확인해야 한다.
  • 메타데이터는 객체 검색, 분류, 외부 연동에 활용될 수 있으므로 표준화된 키 이름을 사용하는 것이 좋다.
  • 객체 삭제 또는 덮어쓰기 작업은 애플리케이션 데이터에 영향을 줄 수 있으므로 객체 경로와 파일명을 확인한 뒤 수행해야 한다.
