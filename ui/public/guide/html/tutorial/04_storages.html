ceph RDB Primary Storage 신규 등록

Infrastructure → Primary Storage → Add Primary Storage 클릭한다.

사전에 ceph에서 확인된 정보를 입력하여 Primary Storage를 추가한다.

OK완료 State가 Up 상태인지 확인한다

ceph Primary Storage 등록 정보 수정 (변경·관리)

RBD Primary Storage 는 접속 정보(Monitor/Pool/User/Secret)와 Scope/Protocol 을 직접 수정할 수 없다.

이 값을 바꾸려면 삭제 후 재등록해야 한다.

* 주의 사항 : 접속 정보를 변경하는 경우 볼륨이 남아 있으면 삭제할 수 없다.
먼저 볼륨을 다른 Primary 로 마이그레이션하여 삭제 대상 ceph의 의존성을 제거해야 삭제가 가능하다.

(Storage → Volumes 목록에서 Storage 필드에서 ceph 의존성 확인 가능)

ceph RDB의 고가용성(HA) 설정

ceph RDB 스토리지를 이용하여 고가용성(HA)를 구성하는 경우 namuVIRT-Management 서버가 호스트를 Down 으로 확정하지 못해 자동 HA 가 동작하지 않는다.

NFS를 공유 스토리지를 추가로 공유하여 HA가 동작하도록 설정이 필요하다.

*참고 : https://docs.cloudstack.apache.org/en/latest/adminguide/reliability.html#ha-enabled-instances

하트비트 풀 공유 NFS 구성

VM 디스크는 모든 호스트가 함께 여는 Ceph RBD(공유 블록 스토리지)에 저장된다.

KVM HA는 별도의 NFS 하트비트 풀에 각 호스트가 하트비트 파일을 기록·갱신하여 HA 기능 활성화를 지원한다

하트비트 풀 Primary Storage 추가

Infrastructure → Primary Storage → Add Primary Storage 클릭한다.

Path에 입력하는 Storage은 하트비트용 풀 스토리지로만 사용한다면 1GB이하의 적은 용량으로 할당 가능하다.

* 단 Ceph RBD 전용 환경에서 VM마이그레이션 하려면 NFS/로컬 Primary가 필요한데(RBD는 변환 직접 대상 불가), 이 하트비트 NFS를 변환 임시 착지 Primary로 겸용할 수도 있다. 이 경우 변환 산출물 용량만큼 커야 하며, 변환 후 볼륨을 RBD로 옮기고 정리해 다시 하트비트 전용으로 사용 권장
