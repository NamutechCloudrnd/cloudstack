AutoScaling Groups

namuVIRT에서 AutoScaling Group은 로드밸런서와 연결된 VM 그룹의 인스턴스 수를 모니터링 지표와 정책에 따라 자동으로 Scale-in/Scale-out 하기위한 기능이다.

AutoScaling Groups 생성 전 사전 작업.

Compute Offering 생성

AutoScaling Group에서 사용할 Compute Offering 규격을 정의한다. AutoScaling Group의 최대 VM 수 만큼 자원이 증가할 수 있으므로 Cluster와 Host에 충분한 Capacity가 있어야 하고 이를 고려하여 Compute Offering을 정의해야 한다.

  • 추가방법 : 사용자 메뉴얼 > Service Offering > Compute Offering 생성 방법 참고

Compute Offering을 추가할 때 필수로 Dynamic Scaling Enabled 옵션을 활성화해야 한다.

Public IP 생성 및 Load Balancer 생성

AutoScaling Group을 활용하기 위해서는 Load Balancer가 필요하다. 이때 사용할 Public IP를 생성하고 Load Balancer Rule을 생성해야 한다. Public IP 는 Guest Network 또는 VPC 의 상세 페이지에서 생성 가능하다.

[그림 1] Public IP 생성

생성된 Public IP의 상세 페이지로 이동하여 Load Balancing 탭에서 정책을 추가할 수 있다. 이때 AutoScale 옵션을 “Yes”로 지정하고 Add버튼을 클릭하여 Public IP가 위치한 네트워크를 선택한다.

[그림 2] Public IP 할당된 네트워크 추가

사전 작업이 완료되면 AutoScaling Group을 추가할 수 있다

  • 추가방법 : 사용자 메뉴얼 > Compute > AutoScaling Group 추가 확인

Guest Network 등록 (선택)

Kubernetes Cluster를 제공하기 위해서는 격리된 네트워크(isolated network)가 필요로 하다. 이는 Advanced network를 사용하는 Zone에서 사용 가능하다.

이때 생성된 isolated network는 Network Offering에서 Source NAT, DHCP, DNS, Load Balancer가 포함된 Offering을 이용해서 Network를 생성해야 한다.

Kubernetes Cluster를 생성할 때 네트워크를 지정하지 않으면 Kubernetes Cluster 전용 Network Offering을 namuVIRT에서 생성한다.

  • 글로벌 설정 > cloud.kubernetes.cluster.network.offering 에 DefaultNetworkOfferingforKubernetesService 가 등록되어 있는 경우 CKS에 대한 네트워크를 자동으로 생성해 준다.

Compute Offering 등록

Kubernetes Cluster를 구성하기 위한 Compute Offering을 구성한다. 이때 Compute Offering의 CPU와 Memory의 사이즈는 Kubernetes ISO 템플릿에서 지정한 CPU와 Memory 사이즈보다 커야 한다.

HA 환경 구성

namuVIRT는 인스턴스를 고가용성으로 활성화하여 지정할 수 있도록 지원한다. 기본적으로 모든 VR(Virtual Router)와 Elastic LB Instance(Load Balancing Instance)는 자동으로 HA를 활성화하여 구성된다.

HA 활성화가 된 인스턴스는 관리대상 호스트의 장애를 감지하고 동일한 가용영역 내 인스턴스를 자동으로 재시작 한다. 이때 동일한 인스턴스가 동시에 실행되는 일이 없도록 보수적인 정책을 유지한다.

HA 기능은 iSCSI 또는 NFS 스토리지(Shared Storage)와 함께 작동하며 Local Storage는 지원하지 않는다.

HA 기능을 검증하기 위해서는 동일한 클러스터 내에 두 개 이상의 호스트가 존재해야 한다.

HA VM 생성

HA Compute Offering을 기반으로 가상머신을 생성한다.

이렇게 생성된 가상머신은 호스트가 장애 발생시 동일한 클러스터의 다른 호스트에서 재시작 된다.

Dedicated HA

Dedicated HA는 HA 전용 호스트를 지정하기 위해 사용된다.

예를 들어 KVM A, B, C가 있다고 가정하였을 때 KVM C 가 Dedicated HA 호스트 라고 지정되어 있으면 KVM A 또는 B에서 장애가 발생되었다고 판단되면 namuVIRT는 KVM C에 재생성 요청을 하게 된다.

Dedicated HA Host를 구성하기 위해서는 tag 기반으로 동작하며, 글로벌 설정에 Tag 지정과 Host에 Tag 지정을 해야 한다.

  • Configuration > Global Setting > Compute > High Availability에서 HA Tag(ha.tag) 지정

[그림 4] Dedicated HA Host 구성을 위한 HA Tag 설정

참고:HA Tag를 지정하면 Management서버를 재시작 해야 한다.

HA Tag를 지정한 다음 호스트에 Tag를 추가하면 Dedicated HA Host 구성이 완료된다.
