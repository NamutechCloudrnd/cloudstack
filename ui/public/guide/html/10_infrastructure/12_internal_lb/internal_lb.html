내부 LB

내부 LB(Internal LB)는 VPC(Virtual Private Cloud) 내부에서만 트래픽을 분산하는 로드밸런싱 기능입니다. 내부 LB 규칙을 생성하고 인스턴스에 적용하면, 로드밸런싱을 담당하는 내부 LB 인스턴스(Internal LB Instance)가 자동으로 생성됩니다. 소스 IP 하나당 하나의 내부 LB 인스턴스가 생성됩니다.

생성된 내부 LB 인스턴스는 Infrastructure > Zones > [Zone 이름] > [물리 네트워크 이름] > Network Service Providers > Internal LB Instance 경로에서 확인하고 관리할 수 있습니다.

내부 LB는 VPC의 네트워크 티어(Network Tier) 내에서 동작합니다. VPC의 주요 구성 요소는 다음과 같습니다.

구성 요소 설명
VPC 가상 라우터를 통해 서로 통신할 수 있는 복수의 격리된 네트워크를 담는 컨테이너입니다.
네트워크 티어(Network Tier) 각 티어는 고유한 VLAN과 CIDR 목록을 가진 격리된 네트워크로, 인스턴스 그룹을 배치할 수 있습니다. 각 티어의 NIC가 게이트웨이 역할을 합니다.
가상 라우터(Virtual Router) VPC 생성 시 자동으로 생성 및 시작됩니다. 네트워크 티어 간 트래픽을 라우팅하며, DNS 및 DHCP 서비스를 제공합니다.
공용 게이트웨이(Public Gateway) VPC에서 인터넷으로 향하는 트래픽을 처리합니다. 최종 사용자에게는 노출되지 않으며, 정적 라우트를 지원하지 않습니다.
사설 게이트웨이(Private Gateway) 사설 네트워크로 향하는 모든 트래픽을 처리합니다.
NAT 인스턴스 인스턴스가 공용 게이트웨이를 통해 인터넷에 접근할 수 있도록 포트 주소 변환(PAT)을 제공합니다.
Network ACL 번호가 매겨진 규칙의 그룹으로, 낮은 번호의 규칙부터 순서대로 평가됩니다.

VPC의 네트워크 아키텍처는 다음 네 가지 기본 옵션으로 구성할 수 있습니다.

  • 공용 게이트웨이만 있는 VPC

  • 공용 게이트웨이와 사설 게이트웨이가 있는 VPC

  • 공용 게이트웨이, 사설 게이트웨이, 그리고 사이트 간 VPN 접근이 있는 VPC

  • 사설 게이트웨이만 있고 사이트 간 VPN 접근이 있는 VPC

라우터 마이그레이션

내부 LB 인스턴스를 다른 호스트로 마이그레이션합니다.

시스템 VM은 동일한 클러스터 내의 호스트 간에만 마이그레이션할 수 있습니다. VMware의 경우 CloudStack 4.16부터 동일한 Pod 내의 다른 클러스터 호스트로도 마이그레이션이 가능합니다.

라우터 마이그레이션 버튼을 클릭하여 마이그레이션 화면을 호출합니다. 대상 호스트를 선택한 후 확인 버튼을 클릭합니다.

내부 LB 규칙 생성 참고

내부 LB 인스턴스는 VPC 티어에 내부 LB 규칙을 추가할 때 자동으로 생성됩니다. 내부 LB 규칙 생성 시 입력 항목은 다음과 같습니다.

항목 설명
이름(Name) 로드밸런서 규칙의 이름을 입력합니다.
설명(Description) 사용자에게 표시될 규칙에 대한 간단한 설명을 입력합니다.
소스 IP 주소(Source IP Address) (선택 사항) 트래픽이 발생하는 소스 IP 주소입니다. 해당 티어의 CIDR에서 IP를 할당받습니다. 지정하지 않으면 네트워크 CIDR에서 자동으로 할당됩니다. 소스 IP 하나당 새로운 내부 LB 인스턴스가 생성됩니다.
소스 포트(Source Port) 소스 IP와 연결된 포트입니다. 이 포트로 들어오는 트래픽이 로드밸런싱됩니다.
인스턴스 포트(Instance Port) 내부 LB 인스턴스의 포트를 입력합니다.
알고리즘(Algorithm) CloudStack이 사용할 로드밸런싱 알고리즘을 선택합니다.

지원하는 로드밸런싱 알고리즘:

알고리즘 설명
Round-robin 각 인스턴스에 순서대로 요청을 분배합니다.
Least connections 현재 연결 수가 가장 적은 인스턴스로 요청을 전달합니다.
Source 동일한 소스 IP의 요청을 동일한 인스턴스로 전달합니다.
