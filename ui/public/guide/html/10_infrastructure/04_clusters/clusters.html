Clusters

Clusters는 인프라의 Host를 같은 운영 경계로 묶어 Instance 배치와 리소스 관리를 수행하는 기능이다. 하나의 Cluster는 Zone과 Pod에 속하며, Hypervisor, CPU 아키텍처, Primary Storage 접근 조건과 함께 관리된다. 운영자는 Cluster의 Allocation state, 리소스 사용량, 설정값, 이벤트를 확인해 신규 배치 가능 여부와 유지보수 영향을 판단한다.

화면 구성

클러스터 목록 화면

  • 화면 위치: Infrastructure > Clusters
  • 설명: 등록된 클러스터의 이름, 할당 상태, 클러스터 유형, 아키텍처, 하이퍼바이저, Pod, Zone 정보를 확인하는 화면이다.

클러스터 목록 화면에서는 인프라에 등록된 Cluster를 표 형태로 조회한다. 화면에는 Name, Allocation state, Cluster type, Arch, Hypervisor, Pod name, Zone 컬럼이 표시된다. 예시 화면에서는 KVM 기반 x86_64 Cluster가 Enabled 상태로 표시되며, 각 Cluster가 특정 Pod와 Zone에 연결되어 있음을 확인할 수 있다. 상단의 Add Cluster 버튼을 통해 신규 Cluster 추가 작업을 시작할 수 있다.

클러스터 추가 입력 화면

  • 화면 위치: Infrastructure > Clusters > Add Cluster
  • 설명: Zone, Pod, 클러스터 이름, Hypervisor, Arch, Dedicated 여부를 입력하여 신규 Cluster를 추가하는 화면이다.

클러스터 추가 화면에서는 Cluster가 속할 Zone과 Pod를 선택한 뒤 cluster name, hypervisor, Arch 값을 지정한다. 화면 예시에서는 KVM Hypervisor와 Intel/AMD 64비트 아키텍처가 선택되어 있으며, Dedicated 옵션은 비활성화되어 있다. 입력값을 확인한 뒤 OK를 선택하면 신규 Cluster 생성 요청이 진행된다.

클러스터 상세 정보 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > Details
  • 설명: 선택한 Cluster의 상태, ID, 관리 상태, 아키텍처, Hypervisor, Pod, Zone 정보를 확인하는 화면이다.

클러스터 상세 정보 화면에서는 선택한 Cluster의 기본 속성과 리소스 요약을 확인한다. 왼쪽 요약 영역에는 Status, Allocation state, ID, CPU, Memory, Pod, Zone 정보가 표시되며, 오른쪽 Details 탭에는 Name, ID, Allocation state, Cluster type, Managed state, Arch, Hypervisor, Pod name, Zone, Dedicated 값이 표시된다. View Hosts 버튼을 사용하면 해당 Cluster에 속한 Host 목록으로 이동할 수 있다.

클러스터 리소스 탭 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > Resources
  • 설명: 선택한 Cluster의 Primary Storage 사용량을 확인하는 화면이다.

Resources 탭에서는 Cluster와 연결된 리소스 사용량을 확인한다. 화면 예시에서는 Primary Storage used 항목과 Allocated 값이 표시된다. 사용량이 0으로 표시되는 경우에도 Host 연결 상태, Primary Storage 연결 상태, 리소스 수집 시점을 함께 확인해야 한다.

클러스터 설정 탭 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > Settings
  • 설명: Cluster 단위 인증서 자동 갱신, CPU/Memory 할당 임계값 등 설정값을 확인하고 조정하는 화면이다.

Settings 탭에서는 Cluster 단위로 적용되는 설정값을 조회하거나 수정할 수 있다. 화면 예시에는 인증서 자동 갱신, 인증서 만료 알림 기간, CPU 할당 용량 비활성화 임계값, CPU 할당 용량 알림 임계값, Memory 할당 용량 비활성화 임계값, Memory 할당 용량 알림 임계값이 표시된다. 이러한 설정은 Cluster의 신규 리소스 배치 가능 여부, 사전 경고, 인증서 관리 동작에 영향을 줄 수 있다.

클러스터 DRS 탭 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > DRS
  • 설명: Cluster 내 Host 간 Instance 재배치 계획을 생성하고 DRS 실행 이력을 확인하는 화면이다.

DRS 탭에서는 Cluster 내 Instance 배치 최적화를 위한 DRS 계획을 생성하고 실행 이력을 확인한다. 화면에는 최대 live migration 수를 입력하는 Max. migrations 항목과 Generate DRS plan 버튼이 표시된다. 현재 알고리즘은 balanced로 표시되며, 하단 표에는 Type, Successful migrations, Status, Created, Events 컬럼이 제공된다. 데이터가 없는 경우 아직 생성된 DRS 계획이나 실행 이력이 없는 상태로 볼 수 있다.

클러스터 댓글 탭 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > Comments
  • 설명: Cluster에 운영 메모를 추가하고 관리자 전용 공개 여부를 지정하는 화면이다.

Comments 탭에서는 Cluster 리소스에 대한 운영 메모를 등록한다. 화면에는 댓글 수, 댓글 입력란, Only visible to administrators 체크박스, Submit 버튼이 표시된다. 운영자는 Cluster 증설, 유지보수, 테스트 목적, 장애 이력 등 관리상 필요한 정보를 댓글로 남길 수 있다.

클러스터 이벤트 탭 화면

  • 화면 위치: Infrastructure > Clusters > Cluster Detail > Events
  • 설명: Cluster와 관련된 이벤트 수준, 유형, 상태, 사용자, 계정, 도메인, 생성 시각을 조회하는 화면이다.

Events 탭에서는 선택한 Cluster와 관련된 작업 이력과 이벤트를 조회한다. 화면에는 Level, Type, State, Username, Account, Domain, Created 컬럼이 표시된다. Cluster 추가, 수정, 비활성화, 삭제, DRS 계획 생성 등 주요 작업 이후 이 탭을 통해 이벤트 발생 여부를 확인할 수 있다.

클러스터 상세 화면의 작업 버튼 영역

  • 화면 위치: Infrastructure > Clusters > Cluster Detail
  • 설명: Cluster 상세 화면 우측 상단의 작업 버튼을 통해 수정, 상태 제어, 삭제 등 관리 작업을 수행하는 영역이다.

Cluster 상세 화면의 우측 상단에는 선택한 Cluster에 대해 수행할 수 있는 작업 버튼이 표시된다. 화면 예시에서는 Edit 버튼에 마우스를 올린 상태이며, 이 외에도 상태 제어, 설정, 삭제 등으로 보이는 작업 아이콘이 함께 배치되어 있다. 각 아이콘의 실제 기능은 UI 툴팁 또는 실행 확인 창을 기준으로 확인해야 한다.

주요 작업

Cluster 목록 조회

  1. Infrastructure > Clusters로 이동한다.
  2. 목록에서 Cluster 이름, Allocation state, Cluster type, Arch, Hypervisor, Pod name, Zone을 확인한다.
  3. 특정 Cluster의 상세 정보를 확인하려면 대상 Cluster 이름을 선택한다.
  4. 신규 배치나 장애 분석 전에는 Allocation state와 Hypervisor, Pod, Zone을 함께 확인한다.

Cluster 추가

  1. Infrastructure > Clusters로 이동한다.
  2. Add Cluster를 선택한다.
  3. Zone과 Pod를 선택한다.
  4. cluster name, hypervisor, Arch를 입력하거나 선택한다.
  5. 전용 리소스로 사용할 경우 Dedicated 옵션을 운영 정책에 맞게 설정한다.
  6. OK를 선택한 뒤 목록에서 신규 Cluster가 표시되는지 확인한다.

Cluster 상세 및 연결 Host 확인

  1. Cluster 목록에서 대상 Cluster를 선택한다.
  2. Details 탭에서 Status, Allocation state, Managed state, Arch, Hypervisor, Pod, Zone을 확인한다.
  3. CPU와 Memory 값이 비정상적으로 표시되면 Host 등록 상태와 리소스 수집 상태를 함께 확인한다.
  4. View Hosts를 선택해 해당 Cluster에 속한 Host 목록을 확인한다.

리소스와 설정 조회

  1. 대상 Cluster 상세 화면으로 이동한다.
  2. Resources 탭에서 Primary Storage 사용량과 할당량을 확인한다.
  3. Settings 탭에서 CPU/Memory 임계값과 인증서 관련 설정을 확인한다.
  4. 임계값을 변경할 때는 신규 Instance 배치 제한과 알림 기준에 미치는 영향을 먼저 검토한다.

DRS 계획 확인

  1. 대상 Cluster 상세 화면에서 DRS 탭을 선택한다.
  2. 현재 Algorithm과 Max. migrations 값을 확인한다.
  3. 필요한 경우 최대 migration 수를 입력하고 Generate DRS plan을 선택한다.
  4. 생성 결과의 Status, Successful migrations, Events를 확인한다.
  5. 운영 Instance가 있는 환경에서는 계획 실행 전 대상 Host, Storage, Network 조건을 함께 검토한다.

댓글 및 이벤트 확인

  1. Comments 탭에서 Cluster 관련 운영 메모를 확인하거나 등록한다.
  2. 메모 등록 시 민감정보를 입력하지 않는다.
  3. Events 탭에서 Cluster 추가, 수정, 삭제, DRS 작업 이력을 확인한다.
  4. 이벤트가 비어 있거나 원인 판단이 어려우면 관련 작업 시각과 다른 운영 로그를 함께 대조한다.

cluster.cpu.allocated.capacity.notificationthreshold CPU 할당률이 지정 임계값을 초과하면 낮은 CPU 가용량 알림을 발생시키는 기준을 설정한다.
cluster.memory.allocated.capacity.disablethreshold Memory 할당률이 지정 임계값을 초과하면 해당 Cluster를 신규 리소스 배치 후보에서 제외하는 기준을 설정한다.
cluster.memory.allocated.capacity.notificationthreshold Memory 할당률이 지정 임계값을 초과하면 낮은 Memory 가용량 알림을 발생시키는 기준을 설정한다.

상태 및 제약 조건

  • Enabled 상태의 Cluster는 신규 Instance 배치 후보로 사용될 수 있다.
  • Cluster의 Allocation state가 비활성화되면 신규 배치 대상에서 제외될 수 있으나, 기존 실행 리소스가 즉시 제거되는 것은 아니다.
  • Cluster 생성 시 선택한 Hypervisor 유형은 이후 해당 Cluster에 추가할 Host와 일치해야 한다.
  • Arch 값은 Template, ISO, Host 아키텍처와 함께 배치 조건에 영향을 줄 수 있다.
  • Primary Storage 사용량이 0으로 표시되더라도 Storage Pool 연결 상태와 Host 상태를 별도로 확인해야 한다.
  • CPU/Memory disable threshold를 낮게 설정하면 Instance 배치가 조기에 제한될 수 있다.
  • DRS 계획은 Host, Storage, Network, Hypervisor 조건을 만족해야 정상적으로 수행될 수 있다.

주의사항

  • Cluster 이름, ID, Zone, Pod 등 환경 고유 값은 운영 환경별로 다를 수 있다.
  • Dedicated 옵션을 활성화하면 리소스 할당 범위가 제한될 수 있으므로 운영 정책에 맞게 설정해야 한다.
  • Cluster 삭제 또는 비활성화 계열 작업은 해당 Cluster에 속한 Host, Instance, Storage 사용 상태에 영향을 줄 수 있다.
  • 작업 아이콘은 모양만으로 기능을 단정하지 말고 UI 툴팁 또는 실행 확인 창을 기준으로 문서화해야 한다.
  • Comments에는 계정 정보, 접속 정보, 비밀번호, 고객사 정보 등 민감정보를 입력하지 않아야 한다.
  • Events 탭이 비어 있어도 관련 작업 이력이 다른 운영 로그나 작업 상태에 남아 있을 수 있으므로 장애 분석 시 함께 확인해야 한다.

이벤트 및 이력 확인

Events 탭에서는 Cluster 추가, 수정, 비활성화, 삭제, DRS 계획 생성과 관련된 이벤트 이력을 확인한다. 이벤트에는 Level, Type, State, Username, Account, Domain, Created 정보가 표시될 수 있다. Cluster 작업 후 장애가 발생하면 작업 시각, 이벤트 상태, 대상 Cluster의 Allocation state, Host 상태를 함께 대조한다.
