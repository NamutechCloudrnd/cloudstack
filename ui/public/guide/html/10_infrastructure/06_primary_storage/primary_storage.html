Primary Storage

Primary Storage는 Instance 디스크와 Volume이 실제로 배치되는 기본 스토리지 풀이다. 용량, 설정, 브라우저, 이벤트를 함께 점검한다.

기본 스토리지 목록 화면

  • 화면 위치: Infrastructure > Primary Storage
  • 설명: 등록된 기본 스토리지의 상태, IP 주소, 범위, 유형, 경로, Cluster, Zone 정보를 확인하는 화면이다.

기본 스토리지 목록 화면에서는 인스턴스 루트 디스크와 데이터 디스크가 저장되는 스토리지 풀 정보를 확인할 수 있다. 화면 예시에서는 Primary-Storage가 Up 상태이며, IP 주소는 10.10.14.129, Scope는 CLUSTER, Type은 NetworkFilesystem, Path는 /export/primary, Cluster는 namu_Cluster, Zone은 namu_zone으로 표시된다. 상단의 Add Primary Storage 버튼을 통해 신규 기본 스토리지를 추가할 수 있으며, 검색과 Metrics 토글을 사용해 조회 방식을 조정할 수 있다.

기본 스토리지 추가 입력 화면

  • 화면 위치: Infrastructure > Primary Storage > Add Primary Storage
  • 설명: 신규 기본 스토리지를 추가하기 위해 범위, Zone, Cluster, 프로토콜, 서버, 경로, Provider 정보를 입력하는 화면이다.

기본 스토리지 추가 화면에서는 스토리지 적용 범위, Zone, Pod, Cluster, 이름, 프로토콜, 서버 주소, 경로, NFS 마운트 옵션, Provider, 스토리지 태그를 입력한다. 화면 예시에서는 Scope가 Cluster, Zone은 namu_zone, Pod는 namu_Pod, Cluster는 namu_Cluster, 이름은 Test-Primary-Storage로 입력되어 있다. 프로토콜은 nfs, 서버는 10.10.14.129, 경로는 /export/primary/로 설정되어 있으며 Provider는 DefaultPrimary로 선택되어 있다.

기본 스토리지 목록 반영 화면

  • 화면 위치: Infrastructure > Primary Storage
  • 설명: 신규 기본 스토리지 추가 후 목록에 Up 상태로 표시되는 화면이다.

기본 스토리지를 추가하면 목록에 신규 스토리지 풀이 표시된다. 화면 예시에서는 기존 Primary-Storage와 신규 Test-Primary-Storage가 모두 Up 상태로 표시된다. 신규 항목은 IP 주소 10.10.14.129, Scope CLUSTER, Type NetworkFilesystem, Path /export/primary/, Cluster namu_Cluster, Zone namu_zone으로 표시된다.

기본 스토리지 상세 정보 화면

  • 화면 위치: Infrastructure > Primary Storage > Primary-Storage > Details
  • 설명: 선택한 기본 스토리지의 상세 정보와 용량 사용률을 확인하는 화면이다.

기본 스토리지 상세 화면에서는 스토리지 이름, ID, IP 주소, 유형, Scope, 경로, 하이퍼바이저, 오버프로비저닝 계수, 디스크 총량, 할당량, 실제 사용량, Cluster 이름을 확인할 수 있다. 왼쪽 요약 영역에는 상태, IP 주소, 디스크 크기, 사용률, 할당률, Cluster, Pod, Zone, 생성 시각이 표시된다. 화면 예시의 Primary-Storage는 Up 상태이며, NetworkFilesystem 유형, KVM, CLUSTER 범위, /export/primary 경로를 사용한다.

기본 스토리지 설정 화면

  • 화면 위치: Infrastructure > Primary Storage > Primary-Storage > Settings
  • 설명: 선택한 기본 스토리지에 적용되는 용량 임계값과 스토리지 관련 설정을 확인하는 화면이다.

Settings 탭에서는 선택한 기본 스토리지 풀에 적용되는 설정값을 확인하거나 수정할 수 있다. 화면 예시에는 스토리지 풀 I/O 정책, 할당 용량 비활성화 임계값, 볼륨 크기 변경 시 할당 용량 임계값, 전체 용량 비활성화 임계값, 대체 엔드포인트, 클러스터 위치 관련 설정이 표시된다. 이러한 설정은 스토리지 풀의 신규 볼륨 배치, 볼륨 크기 변경, 용량 초과 방지 동작에 영향을 줄 수 있다.

기본 스토리지 브라우저 화면

  • 화면 위치: Infrastructure > Primary Storage > Primary-Storage > Browser
  • 설명: 기본 스토리지 내부에 저장된 파일 또는 객체 목록과 연결 리소스를 확인하는 화면이다.

Browser 탭에서는 선택한 기본 스토리지 내부의 저장 항목을 조회할 수 있다. 화면 예시에서는 여러 UUID 형식의 항목이 표시되며, 각 항목의 크기, 마지막 갱신 시각, 연결된 리소스가 함께 표시된다. 연결 리소스에는 ROOT 또는 DATA 볼륨 이름이 표시될 수 있으며, 일부 항목은 Unknown으로 표시된다.

기본 스토리지 이벤트 탭 화면

  • 화면 위치: Infrastructure > Primary Storage > Primary-Storage > Events
  • 설명: 선택한 기본 스토리지와 관련된 이벤트 이력을 확인하는 화면이다.

Events 탭에서는 선택한 기본 스토리지와 관련된 작업 이벤트를 조회할 수 있다. 화면 예시에서는 표시되는 이벤트가 없어 데이터 없음 상태로 표시된다. 이벤트가 기록되는 경우에는 스토리지 추가, 설정 변경, 유지보수, 오류 분석 등의 작업 이력을 확인하는 데 활용할 수 있다.

주요 작업

Primary Storage 추가

  1. Infrastructure > Primary Storage로 이동한다.
  2. Add Primary Storage를 선택한다.
  3. Scope, Zone, Cluster, Protocol, Server, Path, Provider를 입력한다.
  4. 저장 후 목록에서 신규 Storage가 Up 상태로 표시되는지 확인한다.

설정 및 Browser 조회

  1. 대상 Primary Storage를 선택한다.
  2. Settings 탭에서 용량 임계값과 스토리지 정책을 확인한다.
  3. Browser 탭에서 저장 파일과 연결 리소스를 조회한다.
  4. 이상 징후가 있으면 Events 탭으로 작업 이력을 함께 확인한다.

입력 항목

기본 스토리지 추가 입력 화면

항목 설명
Scope 기본 스토리지를 적용할 범위를 선택한다. 화면 예시에서는 Cluster 범위가 선택되어 있다.
Zone 기본 스토리지를 추가할 Zone을 선택한다.
Pod 기본 스토리지를 연결할 Pod를 선택한다.
Cluster 기본 스토리지를 연결할 Cluster를 선택한다.
Name 기본 스토리지 이름을 입력한다.
Protocol 스토리지 접근 프로토콜을 선택한다. 화면 예시에서는 nfs가 선택되어 있다.
Server 스토리지 서버의 IP 주소 또는 호스트명을 입력한다.
Path 스토리지 서버에서 export 또는 공유된 경로를 입력한다.
NFS mount options KVM 호스트에서 NFS 스토리지를 마운트할 때 사용할 옵션을 입력한다.
Provider 기본 스토리지 Provider를 선택한다.
Storage tags 스토리지 배치 정책에 사용할 태그를 입력한다.

기본 스토리지 설정 화면

항목 설명
Kvm storage pool io policy KVM 스토리지 풀의 I/O 정책을 설정한다.
Pool storage allocated capacity disablethreshold 할당 스토리지 사용률이 지정한 값 이상이 되면 낮은 가용 용량 조건에서 해당 풀 사용을 제한하는 임계값이다.
Pool storage allocated resize capacity disablethreshold 볼륨 크기 변경 시 할당 스토리지 사용률 기준으로 해당 풀 사용을 제한하는 임계값이다.
Pool storage capacity disablethreshold 스토리지 실제 사용률이 지정한 값 이상이 되면 신규 할당 대상으로 사용하지 않도록 제한하는 임계값이다.
Sp alternative endpoint 스토리지 풀 대체 엔드포인트를 지정한다.
Sp cluster location 스토리지 풀의 클러스터 위치 정보를 지정한다.

상태 및 제약 조건

  • Up 상태의 Primary Storage만 Volume 생성과 Instance 배포에 정상 사용될 수 있다.
  • 용량 사용률 또는 할당률이 임계값을 넘으면 신규 Volume 생성이나 Instance 배포가 제한될 수 있다.
  • Scope를 Cluster로 설정하면 해당 Storage는 지정한 Cluster에서만 사용된다.
  • 동일 Cluster에 여러 Storage를 둘 때는 태그와 배치 정책을 함께 관리해야 한다.

주의사항

  • 입력한 서버와 경로는 해당 Cluster의 모든 호스트에서 접근 가능해야 한다.
  • 잘못된 경로 또는 권한 설정은 볼륨 생성, 인스턴스 배포, 마이그레이션 실패로 이어질 수 있다.
  • 동일 Cluster에 여러 기본 스토리지를 추가하는 경우, 스토리지 태그와 배치 정책을 확인해 의도한 스토리지로 볼륨이 생성되는지 검증해야 한다.
  • 기본 스토리지의 용량 사용률과 할당률이 높아지면 신규 볼륨 생성이나 인스턴스 배포가 제한될 수 있다.
  • 기본 스토리지 장애는 해당 스토리지에 배치된 인스턴스 디스크와 데이터 볼륨에 직접 영향을 줄 수 있다.
  • 용량 임계값을 과도하게 높게 설정하면 스토리지 부족 상황에서 신규 볼륨 생성이나 인스턴스 배포 실패가 발생할 수 있다.
  • 스토리지 풀 설정 변경은 해당 풀을 사용하는 인스턴스와 볼륨 배치 정책에 영향을 줄 수 있으므로 변경 전 영향 범위를 확인해야 한다.
  • 브라우저에 표시되는 스토리지 내부 항목은 인스턴스 디스크 또는 볼륨 데이터와 연결될 수 있으므로 임의 삭제나 변경을 수행해서는 안 된다.

이벤트 및 이력 확인

Events 탭에서는 대상 Primary Storage와 관련된 작업 이력을 확인한다. 설정 변경이나 장애 분석 시 Details, Settings, Browser 정보와 함께 비교해야 원인을 좁히기 쉽다.
