Zone

Zone은 namuVirt 인프라 배포에서 두 번째로 큰 조직 단위이다. 인프라를 Zone 단위로 구성하면 물리적 격리와 이중화를 제공할 수 있다..

Zone의 구성 요소:

  • Pod: Zone 내에 하나 이상의 Pod가 포함된다. 각 Pod는 호스트 클러스터 및 하나 이상의 기본 스토리지 서버로 구성된다.

  • 기본 스토리지(Primary Storage): Zone 내 모든 Pod에서 공유될 수 있는 기본 스토리지 서버를 포함할 수 있다.

  • 2차 스토리지(Secondary Storage): Zone 내 모든 Pod에서 공유되는 Zone 범위의 자원이다.

Zone은 최종 사용자에게 표시된다. 사용자가 게스트 인스턴스를 시작할 때 Zone을 선택해야 하며, 해당 Zone에서 인스턴스를 생성하려면 사용자의 프라이빗 템플릿을 해당 Zone에 복사해야 할 수도 있다.

Zone은 공개(Public) 또는 프라이빗(Private) 으로 설정할 수 있다. 공개 Zone은 모든 사용자에게 표시되어 누구든지 해당 Zone에서 게스트를 생성할 수 있다. 프라이빗 Zone은 특정 도메인을 위해 예약되며, 해당 도메인 또는 하위 도메인의 사용자만 게스트를 생성할 수 있다.

동일한 Zone 내의 호스트는 방화벽을 통하지 않고 서로 직접 접근할 수 있다. 서로 다른 Zone에 있는 호스트는 정적으로 구성된 VPN 터널을 통해 서로 접근할 수 있다.

목록 조회

Zone 목록을 확인하는 화면이다. 생성된 Zone 목록을 확인하거나 Zone 추가 버튼을 클릭하여 새로운 Zone을 생성할 수 있다.

Zone 추가

Zone 추가 버튼을 클릭하면 Zone 추가 마법사가 시작된다.

namuVirt UI를 통해 새 Zone을 추가할 때 Zone의 물리 네트워크를 구성하고, 첫 번째 Pod, 클러스터, 호스트, 기본 스토리지 및 2차 스토리지를 추가하도록 안내된다.

참고: 다음은 구성 예시이다. Zone 구성 시 네트워크, 스토리지, 호스트 등 실제 구축하는 사이트 환경에 맞는 값을 입력해야 한다.

3단계: 물리 네트워크 및 트래픽 유형 설정

Zone에서 사용하는 물리 네트워크와 트래픽 유형을 설정한다.

기본(Basic) Zone의 트래픽 유형:

트래픽 유형 설명
Guest 최종 사용자가 인스턴스를 실행할 때 발생하는 트래픽이다. 기본 Zone에서는 각 Pod가 브로드캐스트 도메인이 되며 Pod마다 다른 IP 범위를 가진다.
Management 호스트, 시스템 VM, namuVIRT의 내부 통신 트래픽이다. 시스템 VM이 사용할 IP 범위를 구성해야 한다.
Storage 2차 스토리지 VM과 2차 스토리지 서버 사이에서 인스턴스 템플릿 및 스냅샷 전송 시 발생하는 트래픽이다. 고속 템플릿 및 스냅샷 복사를 위해 높은 대역폭 네트워크에서 운영되는 별도의 스토리지 NIC를 사용한다.

권장사항: 관리 트래픽과 게스트 트래픽은 별도의 NIC를 사용하도록 강력히 권장한다.

고급(Advanced) Zone의 트래픽 유형:

트래픽 유형 설명
Guest 최종 사용자 인스턴스 트래픽이다. 격리(Isolated) 게스트 네트워크에서는 각 계정의 네트워크 격리를 위해 VLAN 범위를 예약해야 한다. 공유(Shared) 게스트 네트워크에서는 모든 게스트 인스턴스가 단일 네트워크를 공유한다.
Management namuVirt 내부 자원 간 통신 트래픽이다. 시스템 VM이 사용할 IP 범위를 구성해야 한다.
Public 클라우드 내 인스턴스가 외부 시스템에 접근할 때 발생하는 트래픽이다. 게스트 인스턴스는 Virtual Router를 통해 외부 시스템에 접근한다. Public IP는 Virtual Router를 포함한 시스템 VM의 Public 인터페이스에 할당된다.
Storage 2차 스토리지 관련 트래픽이다. 기본 스토리지 트래픽에는 영향을 미치지 않는다.

각 트래픽 유형의 편집 버튼을 클릭하여 트래픽 라벨을 입력한다.

입력 정보 확인 후 다음 버튼을 클릭한다.

5단계: Pod 네트워크 정보 입력

Pod는 일반적으로 단일 랙에 해당하며, 동일한 Pod 내의 호스트는 동일한 서브넷에 위치한다. Pod는 Zone에 포함되며 하나 이상의 호스트 클러스터와 하나 이상의 기본 스토리지 서버로 구성된다.

항목 설명
이름 Pod의 이름을 입력한다.
예약된 시스템 게이트웨이 관리 네트워크(시스템 예약 IP 범위)의 게이트웨이를 입력한다.
예약된 시스템 넷마스크 관리 네트워크의 서브넷 마스크를 입력한다.
예약된 시스템 시작 IP 시스템 VM이 사용할 IP 범위의 시작 주소를 입력한다.
예약된 시스템 종료 IP 시스템 VM이 사용할 IP 범위의 종료 주소를 입력한다.

참고: 시스템 예약 IP 범위는 클라우드 전체에서 고유해야 한다. 서로 다른 Zone의 호스트가 동일한 프라이빗 IP를 가질 수 없다. 컴퓨팅 서버와 관리 서버에는 시스템 예약 IP 범위 외부의 IP를 사용해야 한다.

입력 정보 확인 후 다음 버튼을 클릭한다.

7단계: 클러스터 정보 입력

클러스터는 호스트를 그룹화하는 방법을 제공한다. 클러스터 내의 호스트는 모두 동일한 하드웨어를 사용하고, 동일한 하이퍼바이저를 실행하며, 동일한 서브넷에 위치하고, 동일한 공유 기본 스토리지에 접근한다. 인스턴스는 서비스 중단 없이 동일한 클러스터 내의 호스트 간에 실시간 마이그레이션(Live Migration)이 가능한다.

항목 설명
클러스터 이름 클러스터의 이름을 입력한다.

입력 정보 확인 후 다음 버튼을 클릭한다.

8단계: 호스트 추가

호스트는 게스트 인스턴스를 실행하는 컴퓨팅 자원을 제공하는 단일 컴퓨터이다. 각 호스트에는 게스트 인스턴스를 관리하기 위한 하이퍼바이저 소프트웨어가 설치되어 있다. namuVirt는 호스트가 제공하는 CPU 및 메모리 자원의 크기를 자동으로 감지한다.

호스트가 namuVirt에서 동작하려면 다음 조건이 충족되어야 한다.

  • 호스트에 하이퍼바이저 소프트웨어가 설치되어 있어야 한다.

  • 호스트에 IP 주소가 할당되어 있어야 한다.

  • 호스트가 namuVirt 관리 서버에 연결되어 있어야 한다.

항목 설명
호스트 이름 호스트의 호스트명 또는 IP 주소를 입력한다.
사용자 이름 호스트 접근 시 사용할 사용자 이름을 입력한다.
비밀번호 호스트 접근 시 사용할 비밀번호를 입력한다.
태그 호스트를 식별하기 위한 태그를 입력한다.

입력 정보 확인 후 다음 버튼을 클릭한다.

9단계: 기본 스토리지 추가

기본 스토리지(Primary Storage)는 클러스터와 연결되며, 해당 클러스터의 호스트에서 실행 중인 모든 인스턴스의 가상 디스크를 저장한다. KVM 및 VMware에서는 Zone 단위로 기본 스토리지를 프로비저닝할 수 있다.

하나의 클러스터 또는 Zone에 여러 기본 스토리지 서버를 추가할 수 있으며, 최소 하나는 반드시 필요한다. namuVirt는 게스트 가상 디스크를 특정 기본 스토리지 장치에 할당하는 것을 자동으로 관리한다.

항목 설명
이름 기본 스토리지의 이름을 입력한다.
범위 스토리지의 범위(Zone 범위 또는 클러스터 범위)를 선택한다.
제공자 스토리지 제공자를 선택한다.
프로토콜 스토리지 프로토콜을 선택한다. (NFS, iSCSI, RBD 등)

입력 정보 확인 후 다음 버튼을 클릭한다.

10단계: 2차 스토리지 추가

2차 스토리지(Secondary Storage)에는 다음 항목이 저장된다.

  • 템플릿(Templates): 인스턴스 부팅에 사용할 수 있는 OS 이미지이며, 설치된 애플리케이션 등 추가 구성 정보를 포함할 수 있다.

  • ISO 이미지: 운영 체제용 부팅 미디어 또는 데이터를 포함하는 디스크 이미지이다.

  • 디스크 볼륨 스냅샷: 데이터 복구 또는 새 템플릿 생성에 사용할 수 있는 인스턴스 데이터의 저장 사본이다.

2차 스토리지의 항목은 Zone 또는 Region 범위로 정의된 스코프 내의 모든 호스트에서 사용 가능한다.

항목 설명
제공자 2차 스토리지 제공자를 선택한다. (NFS, S3, Swift 등)
이름 2차 스토리지의 이름을 입력한다.
서버 2차 스토리지 서버의 주소를 입력한다.
경로 스토리지 경로를 입력한다.

입력 정보 확인 후 다음 버튼을 클릭한다.

HA 비활성화

해당 Zone의 HA(High Availability) 기능을 비활성화/활성화한다.

참고: namuVirt는 시스템 가용성을 높이기 위한 다양한 HA 기능을 제공한다. 관리 서버는 서버가 로드 밸런싱되는 다중 노드 설치로 배포될 수 있으며, 데이터베이스 손실 시 장애 조치를 위해 MySQL 복제 구성이 가능한다. 호스트에 대해서는 NIC 본딩과 스토리지를 위한 별도 네트워크 사용 및 iSCSI 다중 경로(Multipath) 구성을 지원한다.

HA 비활성화/활성화 버튼을 클릭하여 HA 비활성화/활성화 화면을 호출한 뒤 확인 버튼을 클릭한다.

상세 탭

Zone에 대한 상세 정보를 조회하는 화면이다. 해당 Zone의 이름, 아이디, 할당 상태, 유형, 네트워크 유형, 게스트 CIDR, 로컬 스토리지 사용 여부, 보안 그룹 활성화 여부, DNS, 내부 DNS, 전용 여부 등의 정보를 확인할 수 있다.

물리네트워크 탭

Zone에서 사용하는 물리 네트워크를 조회 및 관리하는 화면이다. 물리 네트워크는 Zone 내의 실제 네트워크 하드웨어와 배선을 의미한다. Zone에는 여러 물리 네트워크가 있을 수 있다.

관리자는 물리 네트워크에서 다음을 수행할 수 있다.

  • Zone 내 물리 네트워크 추가/제거/업데이트

  • 물리 네트워크에서 VLAN 구성

  • 하이퍼바이저가 네트워크를 인식할 수 있도록 이름 구성

  • 물리 네트워크에서 사용 가능한 서비스 제공자(방화벽, 로드 밸런서 등) 구성

  • 물리 네트워크에 트렁킹된 IP 주소 구성

  • 물리 네트워크가 전달하는 트래픽 유형 및 네트워크 속도 등 속성 지정

물리네트워크 추가

Zone에 물리 네트워크를 추가하는 기능이다.

물리 네트워크 추가 버튼을 클릭하여 물리 네트워크 추가 화면을 호출한다.

항목 설명
이름 물리 네트워크의 이름을 입력한다.
분리 방법 네트워크 격리 방식을 선택한다. (VLAN 등)
VLAN/VNI VLAN 또는 VNI 범위를 입력한다.
태그 물리 네트워크를 식별하기 위한 태그를 입력한다.
네트워크 속도 물리 네트워크의 속도를 입력한다.
브로드캐스트 도메인 범위 브로드캐스트 도메인의 범위를 선택한다.

확인 버튼을 클릭하여 물리 네트워크를 추가한다.

IPv4 서브넷 탭

IPv4 서브넷은 ROUTED 네트워크 모드를 사용하는 격리(Isolated) 네트워크 또는 VPC의 게스트 네트워크에서 사용할 IP 주소 범위를 Zone 단위로 사전 구성하는 기능이다. 운영자(Root Admin)는 Zone에서 사용할 IPv4 서브넷을 미리 등록해두어야 하며, 등록된 서브넷은 게스트 네트워크 생성 시 할당된다. IPv4 서브넷은 특정 도메인 또는 계정에 전용(Dedicated)으로 할당하거나, 전용 할당을 해제하여 공유 상태로 되돌릴 수 있다.

Zone에 구성된 IPv4 서브넷을 조회 및 관리하는 화면이다.

IPv4 서브넷 추가

Zone에 IPv4서브넷을 추가하는 기능이다.

라우팅 된 네트워크용 IPv4 서브넷 추가 버튼을 클릭하여 IPv4 서브넷 추가 화면을 호출한다.

항목 설명
Subnet 추가할 서브넷을 입력한다.
예약 설정 이 서브넷과 연결할 도메인/계정을 지정할지 여부이다.
계정 이 서브넷과 연결할 계정을 지정한다.
도메인 이 서브넷과 연결할 도메인을 지정한다.

확인 버튼을 클릭하여 IPv4서브넷을 추가한다.

AS 번호 탭

Zone에 구성된 AS(Autonomous System) 번호 범위를 조회 및 관리하는 화면이다.

동적 라우팅(Dynamic Routing) 모드로 네트워크를 생성하려면 운영자(Root Admin)가 사전에 Zone에 AS 번호 범위를 등록해야 한다. 동적 라우팅이 적용된 게스트 네트워크 또는 VPC를 생성하면, 등록된 AS 번호 범위에서 AS 번호가 자동으로 할당되고 가상 라우터(VR)에서 BGP 피어 세션이 자동으로 구성된다.

BGP 피어 탭

Zone에 구성된 BGP 피어(BGP Peer)를 조회 및 관리하는 화면이다.

동적 라우팅(Dynamic Routing) 모드로 네트워크를 생성하려면 운영자(Root Admin)가 사전에 Zone에 BGP 피어를 등록해야 한다. 동적 라우팅이 적용된 게스트 네트워크는 해당 계정이 접근 가능한 모든 BGP 피어에 자동으로 연결된다. BGP 피어는 특정 도메인 또는 계정에 전용(Dedicated)으로 할당하거나, 전용 할당을 해제하여 공유 상태로 되돌릴 수 있다.

BGP 피어 추가 버튼을 클릭하여 BGP 피어 추가 화면을 호출한다.

항목 설명
IP 주소 BGP 피어의 IP 주소를 입력한다.
AS 번호 BGP 피어의 AS 번호를 입력한다.
비밀번호 BGP 피어 세션 인증에 사용할 비밀번호를 입력한다.

확인 버튼을 클릭하여 BGP 피어를 추가한다.

시스템 VM 탭

Zone에 배포된 시스템 가상머신의 상태를 조회하는 화면이다.

namuVirt는 클라우드 내부 구성 및 운영을 위해 시스템 VM(가상 어플라이언스)을 자동으로 구성한다. 이 시스템 VM들은 다음과 같은 서비스를 제공한다.

  • 방화벽(Firewalling)

  • 라우팅(Routing)

  • DHCP

  • VPN

  • 콘솔 프록시(Console Proxy)

  • 스토리지 접근(Storage Access)

  • 스토리지 복제(Storage Replication)

해당 Zone에서 실행 중인 시스템 VM의 이름, VM 상태, Agent 상태, 유형, Public IP, 호스트 등의 정보를 확인할 수 있다.

리소스 탭

Zone에 할당된 자원의 상태를 조회하는 화면이다. 해당 Zone에서 현재 할당량과 할당 가능량을 확인할 수 있다.

namuVirt는 호스트가 제공하는 CPU 및 메모리 자원의 크기를 자동으로 감지한다. 클러스터에 언제든지 호스트를 추가하여 게스트 인스턴스를 위한 용량을 늘릴 수 있다.
