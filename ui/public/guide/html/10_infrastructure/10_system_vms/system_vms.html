System VMs

System VMs는 클라우드 플랫폼이 내부 관리 기능을 수행하기 위해 생성하고 관리하는 시스템 가상머신이다. 일반 사용자 Instance처럼 업무 애플리케이션을 실행하기 위한 대상이 아니며, 플랫폼 기능을 유지하기 위한 관리용 VM으로 이해해야 한다. 관리자는 System VM을 임의로 생성하거나 삭제하기보다 목록과 상세 화면에서 State, Agent state, System VM type, IP 주소, Host, Zone, 이벤트를 확인하여 플랫폼 상태를 점검한다.

System VM 유형에는 웹 콘솔 접속을 중계하는 consoleproxy와 템플릿, ISO, 스냅샷 등 Secondary Storage 관련 작업을 지원하는 secondarystoragevm이 포함된다. System VM은 필요에 따라 플랫폼이 생성, 시작, 중지, 재시작할 수 있으므로 장애 분석 시 각 VM의 역할과 현재 상태를 함께 확인하는 것이 중요하다. 사용자 가이드에서는 조작 방법보다 역할, 조회 위치, 상태 확인 방법, 장애 시 확인 포인트를 중심으로 설명한다.

System VM 목록 화면

  • 화면 위치: System VMs
  • 설명: Zone에 생성된 System VM의 이름, 실행 상태, Agent 상태, 유형, IP 주소, Version, Host, 아키텍처, Zone 정보를 확인하는 화면이다.

System VM 목록 화면에서는 클라우드 운영에 필요한 관리용 VM을 표 형태로 조회한다. 화면에는 Name, State, Agent state, System VM type, IP address, Private IP address, Link-local/Control IP address, Version, Host, Arch, Zone 컬럼이 표시된다. 예시 화면에는 consoleproxy 유형의 v-60-VM과 secondarystoragevm 유형의 s-61-VM이 표시되며, 두 System VM 모두 Running 상태이고 Agent state가 Up으로 표시된다. 상단의 Refresh 버튼으로 목록을 갱신할 수 있고, 필터와 검색 기능을 사용해 특정 System VM을 좁혀 조회할 수 있다.

Secondary Storage VM 상세 정보 화면

  • 화면 위치: System VMs > s-61-VM > Details
  • 설명: 선택한 Secondary Storage VM의 상태, Agent 상태, IP 주소, Gateway, Host, Zone, Template, System Offering 정보를 확인하는 화면이다.

Secondary Storage VM 상세 정보 화면에서는 secondarystoragevm 유형 System VM의 기본 정보를 확인한다. 왼쪽 요약 영역에는 Status, ID, Public IP address, Template, System Offering, Host, Pod, Zone, Created 정보가 표시된다. 오른쪽 Details 탭에는 Name, ID, Agent state, System VM type, IP address, Private IP address, Link-local/Control IP address, Gateway, Host, Arch, Version, Zone 정보가 표시된다. Secondary Storage VM은 템플릿, ISO, 스냅샷 등 Secondary Storage 관련 작업을 지원하므로 해당 기능에 문제가 발생하면 이 화면에서 State, Agent state, Host, IP 주소, Zone을 먼저 확인한다.

Console Proxy VM 상세 정보 화면

  • 화면 위치: System VMs > v-60-VM > Details
  • 설명: 선택한 Console Proxy VM의 상태, Agent 상태, IP 주소, Gateway, Host, Zone, Template, System Offering 정보를 확인하는 화면이다.

Console Proxy VM 상세 정보 화면에서는 consoleproxy 유형 System VM의 기본 정보를 확인한다. 왼쪽 요약 영역에는 Status, ID, Public IP address, Template, System Offering, Host, Pod, Zone, Created 정보가 표시된다. 오른쪽 Details 탭에는 Name, ID, Agent state, System VM type, IP address, Private IP address, Link-local/Control IP address, Gateway, Host, Arch, Version, Zone 정보가 표시된다. Console Proxy VM은 웹 UI에서 Instance 콘솔 접속을 중계하는 역할을 하므로, 웹 콘솔 접속 장애가 발생하면 Console Proxy VM의 State, Agent state, Host, IP 주소, Events를 함께 확인한다.

주요 확인 작업

System VM 목록 조회

  1. System VMs로 이동한다.
  2. 목록에서 Name, State, Agent state, System VM type, IP address, Host, Arch, Zone을 확인한다.
  3. consoleproxy와 secondarystoragevm 유형이 표시되는지 확인한다.
  4. State가 Running이어도 Agent state가 Up인지 함께 확인한다.
  5. 특정 System VM의 상세 정보를 확인하려면 대상 System VM 이름을 선택한다.

Secondary Storage VM 상태 확인

  1. System VM 목록에서 secondarystoragevm 유형의 System VM을 선택한다.
  2. Details 탭에서 Status, Agent state, System VM type, IP address, Private IP address, Link-local/Control IP address, Gateway를 확인한다.
  3. 왼쪽 요약 영역에서 Template, System Offering, Host, Pod, Zone, Created 정보를 확인한다.
  4. 템플릿, ISO, 스냅샷, Secondary Storage 접근 관련 문제가 있으면 Host, Zone, Agent state, Events를 함께 대조한다.

Console Proxy VM 상태 확인

  1. System VM 목록에서 consoleproxy 유형의 System VM을 선택한다.
  2. Details 탭에서 Status, Agent state, System VM type, IP address, Private IP address, Link-local/Control IP address, Gateway를 확인한다.
  3. 왼쪽 요약 영역에서 Template, System Offering, Host, Pod, Zone, Created 정보를 확인한다.
  4. 웹 콘솔 접속 문제가 있으면 Console Proxy VM의 State, Agent state, Host, IP 주소, Events를 우선 확인한다.

장애 시 확인 포인트

  1. System VM 목록에서 대상 VM의 State와 Agent state를 확인한다.
  2. VM 유형이 consoleproxy인지 secondarystoragevm인지 확인해 영향 범위를 구분한다.
  3. Host와 Zone 정보를 확인해 특정 Host 또는 Zone 장애와 관련이 있는지 판단한다.
  4. IP address, Private IP address, Link-local/Control IP address, Gateway 값을 확인해 네트워크 정보가 정상적으로 표시되는지 확인한다.
  5. Events 탭에서 최근 작업 이력과 오류 이벤트를 확인한다.
  6. 화면 정보만으로 원인을 판단하기 어려우면 Management Server 로그와 Host 상태를 함께 확인한다.

상태 및 제약 조건

  • System VM은 플랫폼 운영을 위한 관리용 VM이며 일반 사용자 업무용 Instance가 아니다.
  • System VM의 생성, 시작, 중지, 재시작은 플랫폼 상태와 운영 정책에 따라 수행될 수 있다.
  • 관리자는 System VM을 임의로 생성하거나 삭제하기보다 상태와 이벤트를 확인해 플랫폼 기능 정상 여부를 점검한다.
  • State가 Running이어도 Agent state가 Up이 아니면 해당 System VM의 실제 기능이 정상 동작하지 않을 수 있다.
  • consoleproxy 장애는 웹 UI를 통한 Instance 콘솔 접속에 영향을 줄 수 있다.
  • secondarystoragevm 장애는 템플릿, ISO, 스냅샷 등 Secondary Storage 관련 작업에 영향을 줄 수 있다.
  • System VM의 Host 또는 Zone 배치 정보는 장애 범위와 영향 구간을 판단하는 기준으로 활용한다.

주의사항

  • 화면에 표시되는 System VM 이름, IP 주소, Host, Pod, Zone, ID는 운영 환경마다 달라질 수 있는 예시값으로 다룬다.
  • System VM은 CloudStack 기반 플랫폼이 관리하는 VM이므로 일반 Instance처럼 임의 삭제하거나 강제 종료하지 않아야 한다.
  • 상세 화면의 작업 아이콘은 실제 UI 툴팁 또는 실행 확인 창을 기준으로 기능을 확인해야 한다.
  • Console Proxy VM 관련 문제를 분석할 때는 VM 상태뿐 아니라 사용자 Instance 상태, 네트워크, Management Server 상태를 함께 확인한다.
  • Secondary Storage VM 관련 문제를 분석할 때는 Secondary Storage 연결 상태, Template/ISO/스냅샷 작업 이력, Management Server 로그를 함께 확인한다.
  • IP 주소와 Host 이름은 환경 고유 정보이므로 외부 배포 문서에서는 필요에 따라 일반화하거나 마스킹해야 한다.

이벤트 및 이력 확인

Events 탭에서는 System VM 시작, 중지, 재시작, 삭제 요청, Agent 연결 변화, 장애 관련 이벤트를 확인할 수 있다. 이벤트에는 Level, Type, State, Username, Account, Domain, Created 정보가 표시될 수 있다. System VM 장애 분석 시에는 이벤트 시각, State, Agent state, System VM type, Host, Zone을 함께 비교한다.
