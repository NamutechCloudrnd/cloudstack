VPN 연결

VPN 연결은 namuVirt VPC의 VPN 게이트웨이와 원격 측의 VPN 고객 게이트웨이를 실제로 연결하는 IPsec 터널이다. VPN 연결을 통해 namuVirt 클라우드 인프라와 외부 데이터센터 네트워크를 안전하게 연결하거나, 두 VPC 간의 보안 터널을 구성할 수 있다.

VPN 연결을 생성하기 전에 다음 두 가지가 사전에 준비되어 있어야 한다.

  • VPN 게이트웨이: VPN 연결의 namuVirt VPC 측 엔드포인트이다. VPN 게이트웨이 생성 방법은 사이트간 사설네트워크(VPN) 페이지를 참고하십시오.

  • VPN 고객 게이트웨이: VPN 연결의 원격(고객) 측 엔드포인트 정보이다. VPN 고객 게이트웨이 생성 방법은 VPN 고객 게이트웨이 페이지를 참고하십시오.

참고: namuVirt는 VPC당 최대 8개의 VPN 연결을 지원한다.

목록 조회

VPN 연결 목록을 확인하는 화면이다. 생성된 VPN 연결 목록을 확인하거나 VPN 연결 생성 버튼을 클릭하여 새 VPN 연결을 생성할 수 있다.

목록에서 VPN 연결의 IP 주소, 게이트웨이, 연결 상태 등의 정보를 확인할 수 있다.

VPN 연결 생성

VPN 게이트웨이와 VPN 고객 게이트웨이 사이에 IPsec 터널을 생성한다.

  1. 관리자 또는 일반 사용자로 로그인한다.

  2. 왼쪽 탐색 메뉴에서 네트워크 > 사이트 간 VPN 연결을 선택한다.

  3. VPN접속 생성을 선택한다.

  4. 사이트 간 VPN 연결 생성 버튼을 클릭한다.

  5. 아래 항목을 입력한다.

항목 설명
사이트 간 고객 게이트웨이 ID 연결할 VPN 고객 게이트웨이를 선택한다. 사전에 생성된 VPN 고객 게이트웨이 목록에서 선택한다.
사이트 간 VPN 게이트웨이 ID 연결할 VPN 게이트웨이를 선택한다.
Passive 모드 두 VPC 가상 라우터 간 연결을 설정할 때 사용한다. Passive로 설정된 가상 라우터는 상대방이 연결을 시작할 때까지 대기한다. 두 VPC 중 한쪽에만 설정한다.
  1. 확인 버튼을 클릭한다.

VPN 연결이 생성되면 목록에 해당 연결이 표시된다.

VPN 연결 재시작

VPN 연결을 재시작한다. 연결 상태가 비정상이거나 IPsec 터널을 재협상해야 할 때 사용한다.

  1. 관리자 또는 일반 사용자로 로그인한다.

  2. 왼쪽 탐색 메뉴에서 네트워크 > 사이트 간 VPN 연결을 선택한다.

  3. 재시작 할 VPN 연결을 선택한다.

  4. VPN 연결 재설정 버튼을 클릭한다.

VPN 연결 삭제

VPN 연결을 삭제한다.

  1. 관리자 또는 일반 사용자로 로그인한다.

  2. 왼쪽 탐색 메뉴에서 네트워크 > 사이트 간 VPN 연결을 선택한다.

  3. 삭제할 VPN 연결을 선택한다.

  4. VPN 연결 삭제 버튼을 클릭한다.

  5. 확인 버튼을 클릭하여 삭제한다.

상세 탭

VPN 연결에 대한 상세 정보를 조회하는 화면이다. 해당 VPN 연결의 아래 정보를 확인할 수 있다.

항목 설명
IP 주소 VPN 게이트웨이의 Public IP 주소이다. 원격 측에서 이 주소로 IPsec 터널을 연결한다.
게이트웨이 연결된 VPN 고객 게이트웨이의 원격 IP 주소이다.
상태 VPN 연결의 현재 상태이다. Connected(연결됨), Disconnected(연결 해제), Error(오류) 상태를 나타낸다.
IPSec 사전 공유 키 해당 VPN 연결에 사용된 IPsec 사전 공유 키이다.
IKE 정책 해당 VPN 연결에 적용된 IKE 암호화 및 해시 알고리즘 정책이다.
ESP 정책 해당 VPN 연결에 적용된 ESP 암호화 및 해시 알고리즘 정책이다.

VPC 간 Site-to-Site VPN 연결

namuVirt는 VPC 가상 라우터 간의 Site-to-Site VPN 연결을 지원한다. 이 기능을 활용하면 서로 다른 가용 영역 또는 VPC에 배포된 애플리케이션이 안전한 VPN 터널을 통해 통신할 수 있다.

VPC 간 연결 설정 시에는 한쪽 VPC에 Passive 모드를 적용하는 것이 핵심이다. Passive 모드로 설정된 가상 라우터는 상대방 가상 라우터가 연결을 시작할 때까지 대기한다.

VPC 간 연결 설정 순서

아래 예시에서는 VPC A와 VPC B 두 VPC를 연결한다.

  1. VPC A와 VPC B를 각각 생성한다.

  2. 두 VPC에 각각 VPN 게이트웨이를 생성한다.

  3. 각 VPC를 가리키는 VPN 고객 게이트웨이를 각각 생성한다.

    • VPC A에서 사용할 VPN 고객 게이트웨이: VPC B의 VPN 게이트웨이 IP를 등록한다.

    • VPC B에서 사용할 VPN 고객 게이트웨이: VPC A의 VPN 게이트웨이 IP를 등록한다.

  4. VPC A에서 Passive 모드로 VPN 연결을 생성한다. 고객 게이트웨이는 VPC B를 가리키도록 선택한다. 연결 상태는 Disconnected로 표시된다.

  5. VPC B에서 VPN 연결을 생성한다. 고객 게이트웨이는 VPC A를 가리키도록 선택한다. VPC A의 가상 라우터가 Passive 모드로 대기 중이므로, VPC B의 가상 라우터는 Passive 모드로 설정하지 않는다. 연결 상태는 Disconnected로 표시된다.

  6. 양쪽의 VPN 연결이 모두 생성되면 VPN 터널이 자동으로 시작된다. 잠시 기다리면 (기본값: 30초) 두 VPN 연결 모두 Connected 상태로 변경된다.

용어사전

용어 설명
VPN 연결 (VPN Connection) VPN 게이트웨이와 VPN 고객 게이트웨이를 실제로 연결하는 IPsec 터널이다. namuVirt는 VPC당 최대 8개의 VPN 연결을 지원한다.
VPN 게이트웨이 (VPN Gateway) VPN 연결의 namuVirt VPC 측 엔드포인트이다. VPC당 하나씩 생성되며 Public IP 주소를 가진다.
VPN 고객 게이트웨이 (VPN Customer Gateway) VPN 연결의 원격(고객) 측 엔드포인트 정보를 namuVirt에 등록한 객체이다.
Passive 모드 VPN 연결 시 상대방이 연결을 시작할 때까지 대기하는 모드이다. 두 VPC 간 연결 시 한쪽에만 설정한다.
Connected VPN 터널이 정상적으로 설정되어 양쪽 엔드포인트 간에 트래픽이 흐르는 상태이다.
Disconnected VPN 연결이 생성되었으나 아직 터널이 설정되지 않은 상태이다. 상대방 VPN 연결 생성 후 자동으로 Connected 상태로 전환된다.
IPsec (Internet Protocol Security) 인터넷 통신의 보안을 위한 프로토콜로, 데이터 암호화와 인증을 통해 기밀성, 무결성, 인증을 보장한다.
IKE 정책 (IKE Policy) VPN 터널 Phase-1에서 적용되는 암호화 알고리즘 및 해시 알고리즘의 조합이다.
ESP 정책 (ESP Policy) VPN 터널 Phase-2에서 실제 데이터 트래픽 보호에 적용되는 암호화 알고리즘 및 해시 알고리즘의 조합이다.
