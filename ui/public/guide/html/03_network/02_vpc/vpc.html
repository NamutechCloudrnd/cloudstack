VPC

VPC(Virtual Private Cloud)는 namuVirt 내에서 독립적이고 격리된 네트워크 영역이다. VPC는 전통적인 물리적 네트워크처럼 구성할 수 있는 가상 네트워크 구조를 제공한다. VPC 내에서 원하는 IP 주소 범위(예: 10.0.0.0/16)로 프라이빗 주소를 가진 인스턴스를 실행할 수 있다. 또한 VPC 내에서 Network Tier를 설정하여 IP 주소 범위에 따라 웹/앱/DB 등 기능적 역할별로 인스턴스를 계층화할 수 있다. (최대 4개 Tier 지원)

VPC의 주요 구성 요소

구성 요소 설명
VPC 여러 격리 네트워크의 컨테이너 역할을 하며, 가상 라우터를 통해 내부 네트워크 간 통신을 지원한다.
Network Tier 각 Network Tier는 자체 VLAN과 CIDR 목록을 갖는 격리 네트워크로 동작한다. 인스턴스 그룹을 배치할 수 있으며, 보안 목적으로 VLAN을 통해 다른 Tier와 격리된다.
가상 라우터 (Virtual Router) VPC가 생성될 때 자동으로 생성된다. 각 Tier는 가상 라우터에 인터페이스를 추가하여 Tier 간 통신 및 외부 인터넷 연결을 처리한다.
Public Gateway VPC에서 인터넷으로 나가는 트래픽의 출구점이다. VPC 생성 시 자동으로 생성된다.
사설 게이트웨이 (Private Gateway) VPC의 모든 트래픽이 물리적 네트워크로 나가는 출구점이다.
VPN 게이트웨이 VPC 측의 VPN 엔드포인트이다.
사이트 간 VPN VPC와 데이터센터, 가정 네트워크, 또는 다른 클라우드 네트워크 간의 암호화된 연결을 제공한다.
네트워크 ACL 네트워크 ACL은 인바운드 및 아웃바운드 트래픽을 허용하거나 차단하는 Network Tier 수준의 보안 규칙 집합이다.

목록 조회

VPC 목록을 확인하는 화면이다. 생성된 VPC 목록을 확인하거나 VPC 추가 버튼을 클릭하여 VPC를 생성할 수 있다.

VPC 추가

VPC 추가 버튼을 클릭하여 VPC 추가 팝업을 호출한다.

  1. 관리자 또는 일반 사용자로 로그인한다.

  2. 왼쪽 탐색 메뉴에서 네트워크를 선택한다.

  3. VPC 탭을 선택한다.

  4. VPC 추가 버튼을 클릭한다.

  5. 아래 항목을 입력한다.

항목 설명
이름 VPC 이름을 입력한다.
설명 VPC에 대한 설명을 입력한다.
Zone VPC가 위치할 Zone을 선택한다.
소유자 유형 계정 또는 프로젝트 중 선택한다.
도메인 도메인을 선택한다.
계정 계정을 선택한다.
CIDR VPC 전체에서 사용할 슈퍼 CIDR을 입력한다. 생성하는 모든 Network Tier는 이 CIDR의 서브넷이어야 한다.
VPC 오퍼링 사용할 VPC 오퍼링을 선택한다. VPC 오퍼링에는 가상 라우터를 위한 시스템 서비스 오퍼링과 지원하는 네트워크 서비스 목록이 포함된다.
네트워크 도메인 VPC의 네트워크 도메인 이름을 입력한다.
DNS 이 VPC에서 사용할 커스텀 DNS를 입력한다.
IPv6 DNS 이 VPC에서 사용할 커스텀 IPv6 DNS를 입력한다.
서비스용 네트워크의 라우터에 대한 IPv4 주소 게스트 네트워크를 관리할 가상 라우터의 IPv4 주소를 입력한다.
  1. 확인 버튼을 클릭하여 VPC를 생성한다.

참고: VPC 생성 후 가상 라우터가 자동으로 생성된다.

편집

해당 VPC의 이름, 설명, 네트워크 도메인 등의 정보를 업데이트한다.

  1. 관리자 또는 일반 사용자로 로그인한다.

  2. 왼쪽 탐색 메뉴에서 네트워크를 선택한다.

  3. VPC 보기를 선택한다.

  4. 수정할 VPC를 선택한다.

  5. 편집 버튼을 클릭하여 VPC 편집 화면을 호출한다.

  6. 수정할 항목을 입력한다.

  1. 확인 버튼을 클릭하여 VPC를 편집한다.

VPC 재시작

VPC와 연결된 모든 네트워크 구성 요소(Network Tier, 가상 라우터 등)를 재시작한다. 정리(Clean up) 옵션을 활성화하면 기존 가상 라우터가 삭제되고 새 가상 라우터가 프로비저닝된다.

  1. VPC 재시작 버튼을 클릭하여 VPC 재시작 화면을 호출한다.

  2. 확인 버튼을 클릭하여 VPC를 재시작한다.

VPC 삭제

VPC를 삭제한다.

주의: VPC를 삭제하기 전에 연결된 모든 Network Tier 및 가상머신을 먼저 제거해야 한다.

  1. VPC 삭제 버튼을 클릭하여 VPC 삭제 화면을 호출한다.

  2. 확인 버튼을 클릭하여 VPC를 삭제한다.

상세 탭

VPC에 대한 상세 정보를 조회하는 화면이다. 해당 VPC의 이름, 아이디, 설명, CIDR, 네트워크 도메인, Redundant VPC 여부, 재시작 필요 여부, Zone, 계정, 도메인, Public 인터페이스 MTU 등의 정보를 확인할 수 있다.

네트워크 탭

VPC에 대한 Network Tier(서브넷)를 조회 및 관리하는 화면이다. 서브넷 이름, 상태, CIDR, ACL 등의 정보를 확인할 수 있다.

새 서브넷 추가

VPC의 Network Tier를 추가한다. 각 Network Tier는 VPC의 CIDR 범위 내의 서브넷으로 구성된다.

  1. 새 서브넷 추가 버튼을 클릭하여 새 서브넷 추가 화면으로 이동한다.

  2. 아래 항목을 입력한다.

항목 설명
이름 Network Tier의 이름을 입력한다.
네트워크 오퍼링 네트워크 오퍼링을 선택한다. VPC 내의 Network Tier에는 VPC 전용 네트워크 오퍼링만 선택할 수 있다.
게이트웨이 Network Tier에서 사용할 게이트웨이를 입력한다. VPC CIDR 내의 주소여야 한다.
넷마스크 Network Tier의 넷마스크를 입력한다.
ACL 이 Tier에 적용할 네트워크 ACL을 선택한다.
  1. 확인 버튼을 클릭하여 새 서브넷을 추가한다.

참고: Network Tier에 적용된 네트워크 오퍼링은 나중에 다른 VPC 전용 오퍼링으로 변경할 수 있다.

새 서브넷 가상머신 추가

Network Tier에 가상머신을 추가하여 배포한다.

  1. 가상머신 추가 버튼을 클릭하여 가상머신 생성 화면으로 이동한다.

  2. 아래 항목을 입력한다.

항목 설명
이름 가상머신 이름을 입력한다.
소유자 유형 소유자 유형을 선택한다.
도메인 도메인을 선택한다.
계정 계정을 선택한다.
Zone Zone을 선택한다.
Pod Pod를 선택한다.
클러스터 클러스터를 선택한다.
호스트 호스트를 선택한다.
템플릿 사용할 템플릿을 선택한다.
컴퓨트 오퍼링 컴퓨트 오퍼링을 선택한다.
데이터 디스크 데이터 디스크를 선택한다.
네트워크 가상머신이 배포될 네트워크를 선택한다.
SSH 키 쌍 SSH 키 쌍을 선택한다. (필요 시)
부팅 유형 부팅 유형을 선택한다.
부팅 모드 부팅 모드를 선택한다.
TPM 활성화 TPM 활성화 여부를 선택한다.
  1. VM 시작 버튼을 클릭하여 새 서브넷에 가상머신을 추가한다.

내부 LB 추가

Network Tier에 내부 로드 밸런서(Internal Load Balancer)를 추가한다. 내부 LB는 VPC Tier 내의 가상머신 간 트래픽을 분산한다.

  1. 내부 LB 추가 버튼을 클릭하여 내부 LB 추가 화면을 호출한다.

  2. 아래 항목을 입력한다.

항목 설명
이름 내부 LB의 이름을 입력한다.
설명 내부 LB에 대한 설명을 입력한다.
Source IP 주소 내부 LB의 Source IP 주소를 입력한다. 해당 Tier의 CIDR 내의 주소여야 한다.
Source 포트 내부 LB가 수신할 Source 포트를 입력한다.
가상머신 포트 트래픽을 전달할 가상머신의 포트를 입력한다.
알고리즘 로드 밸런싱 알고리즘(라운드 로빈, 최소 연결, 출발지 기반)을 선택한다.
  1. 확인 버튼을 클릭하여 내부 LB를 추가한다.

Public IP 주소 탭

VPC에 할당된 Public IP 주소를 조회 및 관리하는 화면이다. IP 주소, 상태, 연결된 서브넷, ACL 등의 정보를 확인할 수 있다.

새 IP 주소 가져오기

VPC에 Public IP 주소를 추가로 할당한다. 할당된 IP는 포트 포워딩, Static NAT, 로드 밸런서 규칙 등에 사용할 수 있다.

  1. 새 IP 주소 가져오기 버튼을 클릭한다.

  2. IP 주소를 선택한다.

  1. 확인 버튼을 클릭하여 Public IP를 추가한다.

참고: VPC에서 Source NAT IP는 VPC 생성 시 자동으로 할당되며 해제할 수 없다.

네트워크 ACL 목록 탭

VPC에 할당된 네트워크 ACL 목록 탭이다.

네트워크 ACL 목록 추가하기

VPC에 네트워크 ACL목록을 추가한다.

  1. 네트워크 ACL 목록 추가 버튼을 클릭한다.

  2. ACL 목록 이름을 선택한다.

  1. 확인 버튼을 클릭하여 ACL 목록을 추가한다.

사설 게이트웨이 탭

VPC에 연결된 사설 게이트웨이(Private Gateway)를 조회 및 관리하는 화면이다. 사설 게이트웨이의 IP, 상태, 게이트웨이, 넷마스크, VLAN/VNI 등의 정보를 확인할 수 있다.

사설 게이트웨이는 VPC와 물리적 네트워크(데이터센터 내부 네트워크 등)를 연결하는 데 사용된다.

사설 게이트웨이 추가

  1. 사설 게이트웨이 추가 버튼을 클릭하여 사설 게이트웨이 추가 화면으로 이동한다.

  2. 아래 항목을 입력한다.

항목 설명
물리 네트워크 사설 게이트웨이가 연결될 물리 네트워크를 선택한다.
VLAN/VNI VLAN 또는 VNI 값을 입력한다.
연결된 네트워크 연결할 네트워크를 선택한다.
Public IP 주소 사설 게이트웨이에 할당할 IP 주소를 입력한다.
게이트웨이 사설 게이트웨이의 게이트웨이 주소를 입력한다.
넷마스크 넷마스크를 입력한다.
ACL 사설 게이트웨이에 적용할 ACL을 선택한다.
  1. 확인 버튼을 클릭하여 새 사설 게이트웨이를 추가한다.

참고: 사설 게이트웨이는 Source NAT를 지원하지 않는다.

VPN 게이트웨이 탭

VPC에 연결된 VPN 게이트웨이를 조회 및 관리하는 화면이다.

VPN 게이트웨이는 VPC 측의 VPN 엔드포인트로, 이를 통해 VPC와 외부 네트워크(데이터센터, 원격 사무소 등) 간의 암호화된 사이트 간 VPN 터널을 구성할 수 있다.

VPN 게이트웨이 추가

  1. 사이트 간 VPN 게이트웨이 생성 버튼을 클릭하여 VPN 게이트웨이를 추가한다.

  2. VPN 게이트웨이 IP 주소를 입력하고 확인 버튼을 클릭한다.

참고: VPC당 하나의 VPN 게이트웨이만 생성할 수 있다.

VPN 접속 탭

VPC에 설정된 사이트 간 VPN 연결을 조회 및 관리하는 화면이다. VPN 접속의 IP, 상태, 게이트웨이, IPsec 사전 공유 키 등의 정보를 확인할 수 있다.

사이트 간 VPN 연결 생성

사이트 간 VPN 연결을 생성하려면 먼저 VPN 고객 게이트웨이(VPN Customer Gateway)가 생성되어 있어야 한다.

  1. 사이트 간 VPN 연결 생성 버튼을 클릭한다.

  2. 아래 항목을 입력한다.

항목 설명
VPN 고객 게이트웨이 연결할 VPN 고객 게이트웨이를 선택한다. 사전에 생성된 VPN 고객 게이트웨이 목록에서 선택한다.
  1. 확인 버튼을 클릭하여 VPN 연결을 생성한다.

참고: 하나의 VPN 고객 게이트웨이는 한 번에 하나의 VPN 게이트웨이에만 연결할 수 있다.

가상 라우터 탭

VPC에 대한 가상 라우터를 조회하는 화면이다. 해당 VPC의 가상 라우터 이름, 상태, IP, 버전, 실행 중인 호스트 등의 정보를 확인할 수 있다.

VPC의 가상 라우터는 VPC 생성 시 자동으로 프로비저닝되며, VPC 내 모든 Network Tier 간의 라우팅 및 NAT, DHCP, DNS, 방화벽 서비스를 제공한다.

VNF 기기 탭

VPC에 연결된 VNF(Virtual Network Function) 기기를 조회하는 화면이다. 연결된 VNF 기기의 이름, 상태, IP 주소, 템플릿, OS Display 명, 실행 중인 호스트 등의 정보를 확인할 수 있다.

이벤트 탭

VPC에 관련된 이벤트 정보를 확인하는 화면이다. VPC에서 발생한 다양한 액션과 변경 사항을 쉽게 파악할 수 있다.

코멘트 탭

VPC에 관련된 코멘트 정보를 확인하는 화면이다. 각 사용자별로 해당 VPC에 대한 코멘트 정보를 조회 및 관리할 수 있다.

용어사전

용어 설명
VPC (Virtual Private Cloud) namuVirt 내에서 독립적이고 격리된 네트워크 영역이다. 자체 가상 네트워크 토폴로지를 가지며, 물리적 네트워크와 유사하게 구성할 수 있다.
Network Tier VPC 내의 서브넷이다. 각 Tier는 자체 VLAN과 CIDR을 가지며, VLAN을 통해 다른 Tier와 격리된다.
CIDR VPC 전체 또는 각 Network Tier에서 사용할 IP 주소 범위를 정의한다. 모든 Network Tier의 CIDR은 VPC의 슈퍼 CIDR 내의 서브넷이어야 한다.
ACL (Access Control List) 네트워크에서 트래픽의 접근을 제어하는 보안 기능이다. Network Tier 수준에서 인바운드 및 아웃바운드 트래픽을 허용하거나 차단하는 규칙 집합을 정의한다.
Public IP 외부 접근 허용 목적으로 VM이나 로드 밸런서, 방화벽 등 외부에서 접근해야 하는 리소스에 할당된다. VPC에서 Source NAT IP는 VPC 생성 시 자동으로 할당된다.
사설 게이트웨이 (Private Gateway) VPC의 트래픽이 물리적 네트워크로 나가는 출구점이다. Source NAT를 지원하지 않는다.
VPN 게이트웨이 VPC 측의 VPN 엔드포인트이다. VPC와 외부 네트워크 간의 사이트 간 VPN 터널을 위해 사용된다.
IPsec 사전 공유 키 양쪽 VPN 엔드포인트에서 동일하게 설정되어야 하는 키이다. VPN 터널 인증에 사용되며 외부에 공개해서는 안 된다.
VNI VXLAN(Virtual Extensible LAN)에서 사용하는 개념으로, 물리적인 네트워크를 넘어 여러 데이터센터나 네트워크 구간을 가상화하는 기술에 사용된다.
