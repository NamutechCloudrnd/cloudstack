AutoScaling 그룹

Auto Scaling 그룹은 서비스 부하 또는 정책 조건에 따라 인스턴스 수를 자동으로 조정하는 기능이다. 운영자는 Auto Scaling 그룹을 사용하여 트래픽 증가시 인스턴스를 자동으로 추가하고, 부하가 감소하면 불필요한 인스턴스 를 자동으로 제거하여 서비스 가용성과 리소스 효율을 함께 확보할 수 있다.

namuVIRT 의 Auto Scaling 그룹은 Load Balancer와 연동하여 동작한다. 외부 사용자는 Public IP와 공용 포트로 서비스에 접근하고, Load Balancer는 요청을 Auto Scaling 그룹에 속한 인스턴스의 사설 포트로 전환한다. Scale-Up 으로 인스턴스 가 생성되면 해당 인스턴스 는 Load Balancer Rule에 자동으로 연결되고, Scale-Down 또는 삭제 시 Load Balancer Rule 에서 자동으로 제외된다.

AutoScaling 그룹 목록

Auto Scaling 그룹 에서는 현재 등록된 Auto Scaling 그룹 과 상태, Load balancer 정보 등을 확인할 수 있다. Auto Scaling 그룹은 Load Balancer Rule 과 연결되어 동작하므로, 목록 화면에서는 어떤 Public IP와 포트로 서비스가 노출되고 있는지 확인할 수 있다.

해당 화면에서는 Auto Scaling 그룹 생성, 활성화, 비활성화, 삭제가 가능하며, 목록에서 Auto Scaling 그룹을 선택 시 화면에 버튼이 노출된다.

AutoScaling 그룹 생성

  1. 사전준비

Auto Scaling 그룹을 생성하기 전에는 Auto Scaling을 지원하기 위한 Isolated Network 와 Load Balancer Rule 이 필요하다. Load Balancer Rule 은 Auto Scaling 그룹 생성 화면에서 새로 만드는 것이 아니라, 먼저 Public IP에 생성해 둔 뒤 Auto Scaling 그룹 생성 시 선택하는 방식이다.

사전 준비 흐름은 다음과 같다.

  1. Auto Scaling 지원 네트워크 Offering 생성

    1. Isolated network

    2. dhcp / dns / Source NAT / LB

  2. 해당 Offering 으로 Isolated Network 생성

  3. Isolated network 에 Public ip 할당

  4. Public ip 에 Load Balancer Rule 생성

    1. Zone 선택

Auto Scaling 그룹을 생성할 Zone 을 선택하는 단계이다. Zone 은 일반적으로 하나의 데이터센터 또는 물리적으로 분리된 인프라 영역을 의미하며, 선택한 Zone을 기준으로 Auto Scaling 그룹에서 사용할 네트워크, Load Balancer, 인스턴스 리소스가 구성된다.

  1. 템플릿 선택

Auto Scaling 그룹 에서 Scale-Up 시 자동으로 생성할 인스턴스의 OS 템플릿을 선택하는 단계이다. 선택한 템플릿은 Auto Scaling 정책에 따라 새 인스턴스가 추가될 때 기본 이미지로 사용된다.

Auto Scaling 그룹에서 사용하는 템플릿은 생성되는 모든 인스턴스에 동일하게 적용된다. 따라서 템플릿 내부에는 Auto Scaling 대상 서비스가 자동으로 실행될 수 있도록 초기 설정이 포함되어 있어야 한다.

  1. 컴퓨트 오퍼링

Auto Scaling 그룹에서 Scale-Up 시 자동 생성될 인스턴스의 CPU, Memory, Root Disk 구성을 선택하는 단계로 선택한 컴퓨트 오퍼링은 Auto Scaling 으로 생성되는 인스턴스에 동일하게 적용된다.

항목 설명
컴퓨트 오퍼링 Auto Scaling 인스턴스에 적용할 CPU/Memory 사양 선택
Override root disk offering

Root Disk Offering을 별도로 지정할지 여부 선택

  • 비활성화 : 템플릿 또는 Compute Offering의 기본 Root Disk 구성 적용

  • 활성화 : Disk Offering 목록에서 Root Disk 크기와 성능 정책 별도 선택
디스크 오퍼링 Root Disk에 적용할 Disk Offering 선택

Auto Scaling 그룹은 부하에 따라 인스턴스를 자동으로 생성하므로, 컴퓨트 오퍼링은 실제 서비스 부하를 처리할 수 있는 사양으로 선택해야 한다.

예를 들어 웹 서비스 테스트 환경은 Small 인스턴스 로 시작할 수 있지만, 운영 서비스는 CPU/Memory 사용량을 기준으로 적절한 오퍼링을 선택하는 것이 좋다.

  1. 데이터 디스크

Auto Scaling 그룹에서 생성되는 인스턴스에 추가 Data Disk를 연결할지 설정하는 단계이다. Data Disk를 활성화하면 Scale-Up으로 성생되는 인스턴스에 Root Disk 외 별도의 데이터 볼륨을 추가할 수 있다.

  1. 네트워크 선택

Auto Scaling 그룹에서 생성되는 인스턴스에 연결할 네트워크를 선택하는 단계로 기본 네트워크는 VM 자동 확장을 지원하고 Load Balancer Rule 이 연결된 Isolated network 또는 VPC 네트워크 계층이어야 한다.

선택한 네트워크는 Auto Scaling으로 생성되는 인스턴스의 NIC에 연결되며, Load Balancer는 해당 네트워크에 속한 인스턴스로 트래픽을 전달한다.

항목 설명
네트워크 선택 Auto Scaling 그룹의 인스턴스에 대해서 최소 하나의 네트워크를 선택
새로운 네트워크 생성 필요한 경우 Auto Scaling 용 네트워크를 새로 생성
IP / MAC 주소 필요시 인스턴스에 할당할 IP 또는 MAC 주소 지정

Auto Scaling용 네트워크는 이후 Load Balance Rule과 연결되므로, 네트워크 선택 후 해당 네트워크에 Public IP와 Load Balancer Rule이 정상적으로 구성되어 있는지 확인해야 한다.

  1. 부하 분산

Auto Scaling 그룹에서 사용할 Load Balancer Rule을 선택하는 단계로 선택한 Load Balancer Rule은 외부 요청을 Auto Scaling 그룹에 속한 인스턴스에 속한 인스턴스로 전달하는 역할을 한다.

Auto Scaling 그룹은 Scale-Up으로 인스턴스가 생성되면 해당 인스턴스를 Load Balancer Rule 에 자동으로 연결하고, Scale-Down으로 인스턴스가 제거되면 Load Balancer Rule에서 자동으로 제외된다.

  1. 스케일업 정책

Auto Scaling 그룹에서 인스턴스를 자동으로 추가하기 위한 Scale-Up 조건을 설정하는 단계로 Scale-Up 조건이 충족되면 설정된 최대 멤버 수 범위 내에서 인스턴스를 추가하여 서비스 처리 용량을 확장한다.

Scale-Up 정책은 Scale-Down 정책보다 먼저 평가되며, 최소 하나 이상의 Scale-Up 정책을 수가해야 Auto Scaling 그룹을 생성할 수 있다.

조용한 시간 Scale-Up 수행 후 다음 Scale 동작까지 대기할 시간(초) 입력
카운터 Scale-Up 판단에 사용할 성능 지표 선택

조건 추가 입력한 카운터, Operator, 임계값 조건을 정책 목록에 추가
  1. 스케일다운 정책

Auto Scaling 그룹에서 인스턴스를 자동으로 줄이기 위한 Scale-Down 조건을 설정하는 단계로 Scale-Down 정책의 조건이 충족되면 Auto Scaling 그룹은 설정된 최소 멤버 수를 유지하는 범위 내에서 불필요한 인스턴스를 제거하여 리소스 사용량을 줄인다.

Scale-Down 정책은 Scale-Up 정책 이후 평가되며, 하나 이상의 Scale-Down 정책을 추가해야 Auto Scaling 그룹을 생성할 수 있다.

좌측 요약 영역에서는 Auto Scaling 그룹의 상태와 주요 연결정보를 빠르게 확인할 수 있으며, 우측 탭에서는 상세 정보와 정책 구성을 항목별로 조회할 수 있다.

AutoScaling 그룹 과 가상 머신의 차이

항목 가상머신 Auto Scaling 그룹
개념 사용자가 직접 생성하고 관리하는 단일 인스턴스 정책에 따라 인스턴스 수를 자동으로 늘리거나 줄이는 관리 그룹
생성 방식 관리자가 직접 인스턴스 생성 Auto Scaling 그룹이 템플릿 기준으로 인스턴스 자동 생성
수량 관리 수동으로 생성/삭제 최소/최대 멤버 수와 Scale 정책에 따라 자동 조정
Load Balancer 연동 필요 시 수동으로 LB에 연결 생성된 인스턴스 가 LB Rule 에 자동 연결/해제
주요 목적 고정적인 서버 운영 트래픽/자원사용량 변화에 따른 자동 확장/축소
예시 DB 서버, 관리 서버, 단일 웹서버 웹 서버 풀, API 서버 풀, 트래픽 변동 서비스

즉, 가상 머신은 하나의 서버이고, Auto Scaling 그룹은 여러 가상 머신을 자동으로 관리하는 그룹이다.

  1. AutoScaling 그룹 과 가상 머신의 차이

일반적으로 Auto Scaling 그룹 생성 후 최소 멤버 수만큼 인스턴스가 생성된다. 예를 들어 Auto Scaling 그룹 을 생성할 때 최소 멤버 1, 최대 멤버 2로 설정하면 Auto Scaling 그룹은 최소 1대는 항상 유지해야 하므로, Auto Scaling 그룹 생성 후 인스턴스 가 없으면 최소 1대의 인스턴스를 자동으로 생성한다.
