Shared File System

Shared File System은 여러 클라이언트가 공유할 수 있는 파일 시스템 서비스를 제공한다. 생성 시 오퍼링, 네트워크, 디스크 구성을 함께 확인해야 한다.

  • 화면 위치: Service Offerings > Compute Offerings > Share File System Offering
  • 설명: 공유 파일 시스템 생성에 사용할 컴퓨트 오퍼링의 상세 정보를 확인하는 화면이다.

공유 파일 시스템은 내부적으로 서비스 인스턴스를 생성해 파일 공유 기능을 제공하므로, 생성 전에 사용할 컴퓨트 오퍼링을 확인해야 한다. 화면 예시에서는 Share File System Offering이 Active 상태이며, CPU 2 Core, 1024 MB Memory, thin provisioning, shared storage type으로 표시된다. 이 오퍼링은 공유 파일 시스템 인스턴스의 CPU와 메모리 사양을 결정하는 데 사용된다.

  • 화면 위치: Storage > Shared FileSystems > Create Shared FileSystem
  • 설명: 공유 파일 시스템 생성을 위해 소유자, Zone, 파일 시스템, 네트워크, 오퍼링 정보를 입력하는 화면이다.

공유 파일 시스템 생성 화면에서는 소유자 유형, 도메인, 계정, 이름, 설명, Zone, 파일 시스템 유형, 네트워크, 디스크 오퍼링, 컴퓨트 오퍼링을 입력한다. 화면 예시에서는 Account 소유자 유형, ROOT 도메인, admin 계정, namu_zone, XFS 파일 시스템, test-network, Small Disk 5 GB, CPU 2 Core 1024 MB Memory 오퍼링이 선택되어 있다. 입력값을 확인한 뒤 OK 버튼을 선택하면 공유 파일 시스템 생성을 요청한다.

  • 화면 위치: Compute > Instances
  • 설명: 공유 파일 시스템 생성 후 내부 서비스 인스턴스가 인스턴스 목록에 표시되는 화면이다.

공유 파일 시스템을 생성하면 내부적으로 파일 공유 서비스를 제공하는 인스턴스가 생성된다. 화면 예시에서는 sharedfs-testsharefilesystem-19e256a48eb 이름의 인스턴스가 Running 상태로 표시되며, IP 주소는 10.1.1.222, 호스트는 namutech-ProLiant-DL360-Gen10, 계정은 admin, Zone은 namu_zone으로 표시된다. 이 인스턴스는 사용자가 직접 생성한 일반 업무용 인스턴스와 달리 공유 파일 시스템 기능을 제공하기 위한 서비스 인스턴스로 해석해야 한다.

  • 화면 위치: Storage > Shared FileSystems
  • 설명: 생성된 공유 파일 시스템 목록과 상태, 크기, 스토리지 정보를 확인하는 화면이다.

공유 파일 시스템 목록 화면에서는 이름, 상태, 크기, 스토리지, 계정, Zone 정보를 확인할 수 있다. 화면 예시에서는 test_share_filesystem 항목이 Ready 상태로 표시되며, 크기는 5.00 GiB, 스토리지는 Primary-Storage, 계정은 admin, Zone은 namu_zone으로 표시된다. 상단의 Create Shared FileSystem 버튼을 통해 신규 공유 파일 시스템을 생성할 수 있으며, 목록에서 이름을 선택하면 상세 화면으로 이동한다.

  • 화면 위치: Storage > Shared FileSystems > Shared FileSystem Detail > Details
  • 설명: 선택한 공유 파일 시스템의 기본 정보, 네트워크, 볼륨, 사용률을 확인하는 화면이다.

공유 파일 시스템 상세 화면에서는 이름, 설명, 상태, 파일 시스템 유형, 디스크 오퍼링, 크기, 프로비저닝 유형, 사용률, 디스크 읽기/쓰기 지표를 확인할 수 있다. 왼쪽 요약 영역에는 상태, ID, 디스크 크기, 네트워크, IP 주소, 연결된 인스턴스 이름, 데이터 볼륨, 컴퓨트 오퍼링, 스토리지 풀, Zone 정보가 표시된다. 화면 예시에서는 test_share_filesystem이 Ready 상태이며, XFS 파일 시스템, 5.00 GiB 크기, eth0 IP 10.1.1.222, 데이터 볼륨 sharedfs-DATA-10을 사용하는 것으로 표시된다.

주요 작업

Shared File System 생성

  1. 사전에 사용할 Compute Offering과 Disk Offering을 확인한다.
  2. Storage > Shared FileSystems로 이동한다.
  3. Create Shared FileSystem을 선택한다.
  4. 소유자, Zone, 파일 시스템 이름, 네트워크, Offering을 입력한다.
  5. 생성 후 목록에서 상태가 정상인지 확인한다.

Service Instance 확인

  1. 생성 후 Compute > Instances로 이동한다.
  2. sharedfs- 접두어로 생성된 Service Instance가 표시되는지 확인한다.
  3. Shared File System 상세 화면에서 연결된 Volume, 네트워크, 사용률을 함께 확인한다.

입력 항목

공유 파일 시스템 생성 입력 화면

항목 설명
Owner type 공유 파일 시스템의 소유자 유형을 선택한다. 화면 예시에서는 Account가 선택되어 있다.
Domain 공유 파일 시스템을 생성할 도메인을 선택한다.
Account 공유 파일 시스템을 소유할 계정을 선택한다.
Name 생성할 공유 파일 시스템 이름을 입력한다.
Description 공유 파일 시스템 설명을 입력한다.
Zone 공유 파일 시스템을 생성할 Zone을 선택한다.
Filesystem 공유 파일 시스템 내부에서 사용할 파일 시스템 유형을 선택한다.
Network 공유 파일 시스템 인스턴스가 연결될 네트워크를 선택한다.
Disk Offering 공유 파일 시스템의 데이터 볼륨에 적용할 디스크 오퍼링을 선택한다.
Compute Offering for Instance 공유 파일 시스템 서비스 인스턴스에 적용할 컴퓨트 오퍼링을 선택한다.

상태 및 제약 조건

  • Shared File System은 Service Instance, Data Volume, 네트워크가 모두 정상이어야 Ready 상태를 유지한다.
  • 네트워크 선택은 클라이언트 접근 가능 여부에 직접 영향을 준다.
  • Disk Offering과 크기는 저장 가능한 데이터 용량을 결정한다.
  • 내부 Service Instance는 사용자가 일반 VM처럼 임의 조작하는 대상이 아니다.

주의사항

  • 공유 파일 시스템 인스턴스에 적용할 오퍼링의 CPU와 메모리 사양이 낮으면 파일 공유 서비스의 성능에 영향을 줄 수 있다.
  • 네트워크 선택은 클라이언트의 접근 가능 여부에 직접 영향을 주므로, 공유 파일 시스템을 사용할 인스턴스와 같은 접근 범위인지 확인해야 한다.
  • 디스크 오퍼링과 크기는 저장 가능한 데이터 용량에 영향을 주므로 운영 목적에 맞게 선택해야 한다.
  • 공유 파일 시스템 서비스 인스턴스를 임의로 정지하거나 삭제하면 파일 공유 서비스 접근에 영향을 줄 수 있다.
  • 공유 파일 시스템의 중지, 시작, 재시작, 삭제 작업은 해당 경로를 마운트한 클라이언트의 접근에 영향을 줄 수 있다.
  • 네트워크 또는 IP 주소 변경은 기존 마운트 경로와 접근 설정에 영향을 줄 수 있다.

이벤트 및 이력 확인

상세 화면의 Details, Access, Networks, Metrics, Events 탭을 함께 사용한다. Events 탭에서는 생성·변경 이력을, Metrics 탭에서는 사용률과 읽기/쓰기 지표를 확인한다.
